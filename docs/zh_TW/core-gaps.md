## 優先級排名（重要的缺口）

1. **詞彙管理** — ✅ 已於 2026-07-10 推出：**Terms** 管理器
   （Manage → Terms、`/minimal-admin/terms`）涵蓋所有啟用 REST 的分類法
   搭配切換器、階層分類法使用縮排樹狀結構、內嵌
   建立／編輯（名稱、代稱、父項目、說明），刪除時提供誠實的
   確認，數量連結至已篩選的內容清單，並且 **合併**
   （文章會透過核心本身的重新指派功能移至仍存在的詞彙
   機制，接著刪除來源）。編輯器可透過
   `manage_categories`；每個分類法的功能由核心
   REST 路由。
2. **媒體標題與說明** — ✅ 已推出（v0.11.0 週期）：媒體
   詳細資料視窗現在可在標題與替代文字之外編輯標題與說明，
   攜帶編輯內容的原始值（延遲擷取，使清單維持
   淺色）以及透過 wp/v2/media 儲存。
3. **媒體批次選取／刪除** — ✅ 已推出（v0.11.0 週期）：網格項目與
   清單列帶有核取方塊（Shift 範圍選取、全選）與刪除列
   比照內容清單模式；force=true，逐項處理。
4. **留言批次審核** — ✅ 已推出（v0.11.0 週期）：留言列取得
   核取方塊＋選取頁面，以及一個動作列，其動詞是目前分頁本身的
   動作（Pending 上的 Approve／Spam／Trash、Trash 上的 Restore／Delete，以及其他
   上），逐項套用。
5. **批次變更使用者角色** — ✅ 已推出（v0.11.0 週期）：使用者表格
   增加核取方塊欄（受 edit-users 限制），以及可變更每個項目的列
   立即變更所選使用者的角色；目前使用者會被跳過（避免自我鎖定
   防護）。
6. **每篇文章的格式選擇器** — ✅ 已推出（v0.11.0 週期）：編輯器側邊欄
   具有 Format 選擇器，受目前主題宣告 post-format
   支援（與 wp-admin 相符），透過 wp/v2 的原生 `format` 儲存
   欄位。啟動載荷會攜帶支援的格式。

## 逐區域狀態

### Customizer 與主題選項 — 部分支援，主要是刻意如此
已涵蓋：網站識別資料位於 Settings → General（標題、標語、網站圖示
完整上傳流程、網站位址、管理員電子郵件）；首頁設定位於
Settings → Reading（最新文章或靜態頁面，含頁面選擇器）；截至
v0.11.0 週期、**Custom CSS**（`wp_custom_css_post`，Customizer 的
「Additional CSS」）會在 Settings → Design 中編輯
`minimal-admin/v1/custom-css`（edit_css cap、每個主題的樣式表、結構
驗證，與 Customizer 拒絕行為一致）。自訂標誌與網站
語言已在 v0.20.0 週期推出（Settings → Site：標誌受限於
透過 `minimal-admin/v1/site-logo` 支援佈景主題自訂標誌，語言
`minimal-admin/v1/site/language`，儲存時下載套件）。缺少：其他
佈景主題模組、FSE 全域樣式。判定：識別資訊＋首頁＋Custom CSS＋
標誌＋語言是日常範圍，且已涵蓋；真正的 Customizer
而全域樣式確實屬於長尾功能。

### 外觀 — 在關鍵位置已涵蓋
Menus（含拖曳重新排序）與傳統小工具已完整建置；主題
在 Extensions 下安裝／啟用／更新／刪除。範本／FSE 編輯、
背景與頁首圖片：依設計不在範圍內。

### 主題整合 — 已稽核的前沿（2026-07-30）
在 CLASSIC 主題上，日常範圍已涵蓋：Menus、Widgets、標誌、圖示、
自訂 CSS、首頁。缺口集中在區塊主題與主題建構器，
已於 v0.23.0 進行實證驗證：

1. **區塊主題在沒有替代方案時失去優勢（L，需要設計）。**
   當 `wp_is_block_theme()` 時，Minimal 會正確隱藏 Menus 與 Widgets
   （`B.site.blockTheme`），但沒有任何功能介入：沒有導覽編輯
   （`wp_navigation` 文章在 REST 上與 Menus 管理器具有相同的對等性
   如同傳統選單目前已支援的功能），不提供範本／範本部件清單，並具備
   Site Editor 深層連結，沒有全域樣式摘要。區塊主題網站
   使 Minimal 從「管理員」降為「內容管理員」。範圍明確的建置，
   在此項目內排序：導覽優先（實際日常工作、現有
   Menus UX 轉移），接著是唯讀 Design 卡片（啟用中的主題及其
   範本／部分顯示為「Edit in Site Editor ↗」列，目前的調色盤）。
   Site Editor 畫布本身是永久的外部連結（理由與
   表單建構器）。
2. **建構器主題範本不可見（M）。** `elementor_library` IS
   已公開 REST，但未 `viewable`，因此內容切換器（正確地）
   會跳過它，也就是說標頭／頁尾位於 Elementor Theme 中的網站
   Builder 沒有列出這些範本的 Minimal 介面。同樣的情況也適用於
   Bricks／Divi 範本區域。符合現有的頁面建構器介面卡
   核心主張：列出、標示類型（標頭／頁尾／彈出視窗／封存），顯示
   顯示條件為唯讀，並深層連結至建構器畫布。
3. ~~**每個擴充功能的自動更新切換（S）。**~~ **已於 2026-08-04 發布**
   （v0.23.0 週期）：外掛與主題卡片都透過
   `minimal-admin/v1/auto-updates`（相同選項寫入
   `wp_ajax_toggle_auto_updates`，清除過時項目；受限於
   `wp_is_auto_update_enabled_for_type` 伺服器端與用戶端）。Suite
   `tests/auto-updates.test.js`.
4. ~~**佈景主題即時預覽（S）。**~~ **已於 2026-08-04 發布**（v0.23.0
   週期）：非啟用主題卡片上的即時預覽連結：Customizer 適用於
   區塊主題的 `site-editor.php?wp_theme_preview=`
   （`block` 旗標現在隨 `minimal-admin/v1/themes` 傳遞）。
5. **超出狀態的批次編輯（M）。** 內容批次列可處理狀態／
   移至垃圾桶／還原／刪除，但不支援 wp-admin 批次編輯的「加入這些
   分類／為選取的文章設定作者」。
6. ~~**同步模式（S-M）。**~~ **已於 2026-08-04 發布**（v0.23.0 週期）：
   wp_block 通過可檢視閘門的允許清單（`slimContentTypes`）→ 一個
   Content 切換器中的 Patterns 項目，具備標準列機制
   （前端檢視／預覽已抑制，無法公開查詢）；斜線
   選單＋⌘/ 選擇器「Your patterns」（已同步 → `wp:block {"ref":N}`
   參照區塊、靜默插入；未同步 → 透過
   `insertPatternIslands`）；編輯器原生開啟 `/editor/blocks/{id}`
   搭配同步編輯提示與自動精簡的側邊欄；＋ New → Pattern。
   注意：`wp_pattern_sync_status` 在 REST 中是頂層唯讀項目；
   寫入會經由 `meta.wp_pattern_sync_status`。套件
   `tests/user-patterns.test.js`.
7. **Classic Customizer 主題選項 — 維持外部連結。** 任意
   佈景主題模組（色彩、標頭／背景圖片、每個佈景主題的區段）
   沒有結構描述的每個主題反覆調整；Customizer 深層連結是
   誠實的答案，判定與先前相同。

### 分類法 — 已涵蓋
Terms 管理器已於 2026-07-10 推出（請參閱優先級 #1）。唯一的伺服器
新增項目是 `minimal-admin/v1/terms/merge`；其餘全部使用核心 REST。
截至 v0.11.0 週期，Terms 已併入 **Structure** 頁面（Post
Types／Taxonomies／Terms 分頁，而不是獨立的導覽項目，以便維持
MANAGE 群組不足。分頁個別控管：Post Types 與
分類法需要 `manage_options`，Terms 只需要 `manage_categories`，因此
編輯器的 Structure 項目只顯示 Terms 分頁（標示為「Terms」以
它們），而管理員可看到全部三項。`/minimal-admin/terms` 路由與
⌘K「Manage categories & tags」指令仍可運作，並會進入 Terms 分頁。

### Tools — System 頁面強大，但缺少一次性工具
System 頁面完整涵蓋診斷功能（健康檢查、資料庫表格、自動載入
權重、cron 健康狀態、偵錯切換＋日誌檢視器、整合登錄表、
擴充功能資訊清單、複製為 Markdown 的報告）。Loopback 與 REST 自我檢查
健康列已於 2026-07-10 推出（核心自身的 Site Health 測試，快取 15
分鐘），Tools 卡片會深層連結至一次性工作（Site Health、
匯出／匯入、GDPR 匯出／刪除）：偶發性處理仍留在 wp-admin，一
依設計離開。自 v0.22.0 週期起，Database 卡片也成為
入口：其最大資料表列與「瀏覽全部」連結會開啟唯讀
資料庫檢視器（`/minimal-admin/database`，也可在 ⌘K 中使用；刻意不設為導覽
項目）。寫入功能與 SQL 主控台在此仍是永久的非目標
(`native-editors.md`).

### Settings — 日常選項已涵蓋，兩個畫面較薄弱
目前可寫入：General（標題、標語、圖示、URL、管理員電子郵件、時區、
日期／時間格式、星期起始日、預設角色、會員資格、維護、預設
管理員）、Writing（預設分類／格式、表情符號）、Reading（首頁、
每頁文章數、搜尋可見度）、Discussion（預設留言／引用狀態、
審核、需要註冊、啟用／停用頭像）、Permalinks（結構＋
基礎）、Spam（提供者卡片＋不允許的金鑰）、Connectors（WP 7.0 的
連接器登錄：提供者金鑰由核心端遮罩與驗證，
針對 wp-config／env 金鑰的來源誠實性、伴隨外掛安裝於
位置），並在 Site 分頁加入網站標誌與網站語言，因為 v0.20.0
週期。缺少：整個 Media
設定畫面（縮圖大小、月份／年份資料夾）、
`posts_per_rss`／feed 摘要，以及大部分 Discussion 矩陣（串接
深度、每頁數量、先前核准的捷徑、關閉後天數、通知
電子郵件、頭像評分／預設）。判斷：缺少的是一次設定的組態；
只有在留言密集型網站提出需求時，才增加 Discussion 深度。

### 使用者 — 已達到或超越對等程度
清單、搜尋、角色、新增／編輯、刪除並重新指派內容、密碼
重設、寄送電子郵件、終止工作階段、批次變更角色（v0.11.0 已發布）、
應用程式密碼（「AI Access」含產生的代理指南）。
所有長尾個人資料欄位已於 v0.17.0 在 /minimal-admin/profile 推出
頁面（名字、姓氏、個人簡介、網站、每位使用者的語言與自動
套件安裝、前端工具列偏好設定）。應用程式密碼
以及刪除時重新指派，比傳統介面呈現得更好。

### 媒體 — 網格穩固，編輯功能已跟上
具備類型篩選／搜尋／分頁的網格、多檔上傳、拖放、圖片
編輯器（旋轉／裁剪為新副本）、精選圖片流程、刪除、複製 URL、
標題／說明編輯與批次刪除（兩者皆已於 v0.11.0 推出）。
未附加篩選器（核心 parent=0）、月份篩選器（minimal-admin/v1/media/months
組合框 → 前後時間範圍）以及詳細資料視窗的「Attached to」列
搭配編輯器跳轉功能的項目已於 2026-07-17 全部發布（v0.18.0 週期、套件
media-polish）。資料夾：不是
核心功能（Minimal 擁有的樹狀結構會成為第五種資料夾標準，且不可見
至 wp-admin 與建構器選擇器），但先前「長尾、跳過」的判定
已於 2026-07-16 修訂：FileBird＋Real Media Library＋Folders 合計超過 400k
安裝，因此以瀏覽優先的提供者合約成為 Wave D 的一部分
`docs/plugin-support.md`。Wave D 已於 2026-07-17 推出（v0.18.0 週期）：
`minimal_admin_media_folders` 提供者篩選器
（`includes/adapters/media-folders.php`）以及隨附的 FileBird、Real Media
由 Premio 提供者提供的 Library 與 Folders；Media 檢視中有資料夾選擇器
篩選一般 wp/v2/media 查詢（搜尋、類型分頁、未附加項目與
分頁持續運作，每個資料夾最新 500 個），以及移至資料夾的批次
動作會使用各提供者選用的 `move` 可呼叫項目。Suite
`tests/media-folders.test.js`。移動仍以瀏覽優先：Minimal 從不擁有
自己的資料夾樹。

### 留言 — 完整支援單列與批次
待審核／已核准／垃圾／回收桶分頁，完整的逐列審核，批次
審核，依分頁提供動詞（已於 v0.11.0 推出），內嵌回覆
（像核心功能一樣自動核准）、內容選單。最後兩個缺口已在
v0.20.0 週期：內嵌留言編輯（文字始終可編輯；作者姓名／電子郵件可供
訪客留言）與封鎖留言者（將作者的電子郵件或 IP 新增至
核心的不允許清單，可在 Settings → Comments 中查看，並提供 Undo）。

### 多網站 — 非目標，但能合理降級
存在防禦性閘控（`manage_network_users`、超級管理員檔案修改
檢查、System 報告列）。沒有網路介面，也沒有可見的嚴重故障
子網站。

### 結構觀察 — 僅限 REST 是硬性邊界
任何未公開至 REST 的內容，依設計對 Minimal 而言都是不可見的：CPT 與
沒有 `show_in_rest` 的分類法（介面會標示它們）、未註冊的 meta、
自訂狀態。這是刻意如此，而且值得保留；這就是
讓清單檢視保持快速且安全。
