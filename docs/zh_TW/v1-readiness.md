# v1.0 就緒——稽核與 v0.17.0 章程

*撰寫於 2026-07-16、v0.16.0 時，根據對外掛、面向作者的完整稽核
文件（包括由專案新手進行的新鮮視角閱讀），以及路線圖
文件。這是 v0.17.0 週期的工作章程。*

v1.0 的門檻不在於功能數量，而在於 Minimal 必須能夠履行兩項承諾
大聲說出來：

1. **外掛作者享受串接體驗。** 稱職的 WordPress 開發者可以將其
   外掛在一個下午內整合到 Minimal，而不必閱讀 Minimal 的原始碼，並且知道
   契約不會在這些情況下遭到破壞。
2. **外掛作者無法濫用 Minimal。** 外掛註冊的任何內容都無法取得
   使用者未要求的注意力，而外掛註冊的所有內容都可能
   被使用者靜音。WordPress 在通知系統上輸掉了這場戰鬥；Minimal
   必須靠架構與使用者控制取勝，而不是靠政策文件。

## 目前已正常運作的部分（保留，並且更大聲地說出來）

- **此架構天生具備抗濫用能力。** 第三方 PHP 永遠不會掛鉤
  進入 Minimal 的呈現路徑，第三方 HTML/CSS/JS 永遠不會抵達 SPA。
  整合是純資料 descriptor；Minimal 會在邊界處跳脫所有值。
  整類 wp-admin 濫用（任意管理員 HTML、巨型橫幅、虛假
  按鈕）在此不存在。這是目標 #5，而且它成立。
- **通知已經解決。** 外掛無法將任何內容注入 Minimal 的
  通知面板。他們的 wp-admin 通知只會透過擷取抵達：
  縮減為文字、嚴重性與最多三個連結，並歸因於其擁有者，
  使用者可透過 Undo 隱藏，動作連結在背景執行。這
  正是 WordPress 通知問題的確切答案，而且它應該是一項
  標題級主張，而不是變更日誌的註腳。
- **快速入門的效益比例。** 二十行宣告式程式碼即可產生分頁、
  可搜尋、具能力閘控的管理檢視，零 JavaScript 且無需建置步驟。
- **Integrations 卡片。** 顯示所有已註冊項目的即時登錄，並標示
  依外掛處理，並標記契約問題，而不是靜默失敗。大多數
  生態系統永遠不會建立這個。
- **書面相容性承諾**（僅新增、棄用期限、「按鍵
  不在此頁面上是內部項目」），以及真正
  易讀。五十多個隨附介面卡證明這些原語能跨越不同場景泛化
  四種不同的設定結構框架。
- **品質標準**：約 150 個瀏覽器測試套件，在乾淨環境與
  生產規模網站，零主控台錯誤閘門。

### 作者體驗

1. **快速入門被埋得很深。** for-plugin-authors.md 以 19 列 hooks 表開頭
   表格、檔案慣例與相容性區段，然後才迎來第一個成果。
   初次使用者必須先瀏覽 `minimal_admin_visibility_providers`，才能看到
   他們需要的唯一篩選器。
2. **extension-api.md 是個陷阱。** 它是最初的提案文件，標題仍為
   "(proposal)"，仍由 readme 連結，其範例使用了會
   不存在於已隨附的詞彙中（`stats`，舊版 `tabs` 形狀）。兩個
   相互衝突的描述元方言，沒有橫幅。
3. **自訂資料表路徑沒有教學。** 多數表單／記錄外掛會將資料儲存在
   自訂表格。文件中的答案是「閱讀 Gravity SMTP adapter」。該 shim
   是多數情況，值得附註解的逐步導覽，而不是原始碼
   指標。
4. **cap 語意分散各處，而參考配接器教導了不同的
   模式，而不是文件**（介面 `cap: 'read'` 加上介面卡端閘門，
   GF 先例，但未記錄）。
5. **沒有螢幕截圖。** 作者選擇 `format` 值、詳細 `kind`s 與狀態
   盲目配置。
6. **圖示規範不一致。** 文件列出 11 個圖示名稱；內建配接器使用
   不在清單上的名稱；編輯器指令描述的是第三種詞彙。
7. **缺少基本資訊**：每個按鍵的必要／選用標示、引入版本註記、
   i18n 指引、`manage` 與 `views` 的區別、`group` 值清單，以及一
   "test your adapter" 區段（Playground 藍圖已存在，但作者
   指南完全沒有提到它）。

### 濫用防護

8. **沒有使用者覆寫功能。** 使用者無法隱藏或靜音外掛的介面、編輯器
   面板、調色盤項目或 Minimal UI 中的斜線指令。使用者自主權
   其他每項控制的後盾，而它目前尚不存在。
9. **沒有位置或數量預算。** 任何外掛都可以宣稱 `group: 'workspace'`，
   註冊任意數量的介面，在 ⌘K 調色盤中加入無限項目
   （每個介面都會成為由外掛控制標籤的面板列），並放入
   預設斜線選單中的項目。「workspace 用於收件匣形狀」
   規則只是已記錄的慣例，沒有任何地方強制執行。
10. **外部連結未統一標示。** Descriptor `href` 動作與
    狀態卡片連結可攜帶任何 URL；部分渲染網站會加入 ↗，但這並非
    一項保證，因此列動作可能會無聲地成為升級連結。
11. **未說明且沒有後果的規範。** 文件從未說明外掛會受到什麼處置
    提供促銷標籤或催促形狀介面的整合。

## v0.17.0——外掛作者週期（提議範圍）

兩條路線，皆服務於上述閘門。

### 路線 A：作者愉悅度

- **文件重構**（G6）：先放快速入門；將 hooks 表降級為
  參考區段；拆分過長的表格儲存格；說明 `manage` 與 `views` 的差異，
  `group` 詞彙、上限模式（包括介面卡端閘門
  先例作為一等文件化模式）、必要與選用，以及
  依版本。加入標準圖示清單（由 `icon()` 對映生成
  因此不會漂移）。
- **shim 教學**（G1）：帶註解的逐步指南，為某個
  虛構 custom-table plugin，從頭到尾，最後到達 Integrations
  顯示綠色的卡片。將完成的範例作為一個小型真實外掛
  (`docs/examples/` 或獨立儲存庫），供作者複製，並加入
  Playground 藍圖，讓「試用 API」只需按一下。
- **螢幕截圖**涵蓋每個原語（介面清單、詳細資料類型、狀態卡片、
  設定閘門、設定檢視、編輯器面板、斜線項目）都以相同方式擷取
  行銷截圖就是這樣。
- ~~**The forms-family companion**~~ *(已於 2026-07-16 發布，與該項目同日
  要求重新審查：「讓你的表單外掛成為一等
  Forms provider" 區段——包含每個表單動態分頁的完整 descriptor，

### 路線 B：濫用防護

- **隱藏任何整合**（G2）：針對介面提供每位使用者的隱藏功能（導覽右鍵與
  整合卡片上的控制項）、編輯器面板、外掛的調色盤
  項目與斜線命名空間。互動形狀與通知 Hide 相同（使用者中繼資料、
  復原提示，能在重新註冊後保留）。
- **注意力預算**（G3）：在 `Minimal_Admin_Surfaces` 與用戶端中強制執行——
  工作區位置需要一個收件匣形狀的集合（驗證器規則）；
  每個外掛對預設斜線項目與調色盤列設定上限，並自動
  降級為僅搜尋；單一擁有者的表面超過 N 個時會合併為
  一個導覽項目，搭配現有的系列切換器機制。
- **外部連結提示保證**（G4）：所有介面共用一個
  描述元 href；站外連結一律取得 ↗ 並在新分頁中開啟；
  驗證器會標記站外 href，因此 Integrations 卡片會顯示這些項目。
