# 編輯器路線圖 — 長期計畫

*最後根據 v0.24.0（未發布）於 2026-08-06 的程式碼完成狀態驗證。*

**論點：編輯器就是銷售功能。** Minimal Admin 起初是「更平靜的管理介面」，但
編輯器是產品成敗的關鍵。管理介面的其餘部分只是配角 —
優秀的配角，但沒有人會為了更好的外掛畫面而切換管理介面。人們
將工具切換至不同的「寫入位置」。

## 為什麼這是可行的

- **需求已獲證實且尚未被滿足。** Classic Editor 擁有五百萬以上的活躍
  在 Gutenberg 發布多年後才安裝 — 持續支持「不是區塊編輯器」的選擇，
  目前由凍結的技術提供。Minimal 是現代答案：流暢支援 Markdown、
  即時、平靜。
- **鎖定疑慮已解決，這就是護城河。** 每一個過去的「安心寫作」
  WordPress 編輯器死於兩種恐懼之一：*我的內容被困在你的格式中*
  或「*你的編輯器會摧毀我的版面*」。Minimal 儲存原生 Gutenberg 標記（開啟任一
  永遠編輯文章）以及區塊島嶼保留複雜版面
  位元組完全一致。沒有競爭者能講述這個故事；Gutenberg 本身也無法提供「平靜」
  其中一半。
- **寫作使用情境佔編輯的 90%。** 段落、標題、清單、引文、程式碼、
  圖片、偶爾還有表格與嵌入。Minimal 的編輯器已經能完成全部這些操作，並且
  Markdown 慣例、可運作的復原，以及採用網站真實樣式的預覽。

## 定位

**「WordPress 的寫作編輯器。」** 不是「功能比
Gutenberg」— 不同工作使用不同工具。Gutenberg 是版面配置工具；Minimal 是
撰寫內容的地方；islands 和單鍵交接是兩者之間的接縫。
說「那是 Gutenberg 的工作」是策略，不是需要道歉的限制。

「可運作」的標準：**真實正式網站上的每篇文章都能被撰寫並
在 Minimal 中編輯，完全不必開啟區塊編輯器一次。**Dogfooding 是
roadmap 的裁判。

## 建置 v0.5.x 的心得（細節痛點帳冊）

編輯器會以一千種細小行為接受評判，而 contenteditable 在每一項上都會反抗
一項。到目前為止的帳冊，全部已修復並通過回歸測試：Chrome 重新平衡空白
在行內邊界進行破壞性操作；`insertHTML` 將 `<code>` 重寫為樣式 span；
清單會巢狀於其來源段落內；整個區塊刪除會將相鄰項目合併到
殘留外殼；不可編輯的島嶼會因單次相鄰 Backspace 而消失；選取會消失
進入任何 modal；`execCommand('strikeThrough')` 會輸出過時標籤；對齊
透過 `justify*` 寫入樣式，而序列化器會將其剝除。**每項未來功能都會為
這類對抗**——瀏覽器層級的 Playwright 驗證迴圈並非可有可無
額外負擔，這正是編輯器贏得信任的方式。

2026-07-11 有兩項瀏覽器介面定位推論加入帳冊：任何
必須在視覺上跟隨捲動內容的項目，位於捲動容器內的
內容座標（固定定位的介面每個捲動影格都追逐，會落後於
合成器與彈性過度捲動報告在穩定前都不會顯示任何內容 —
區塊膠囊晃動；ResizeObserver 會在真實重排時重新錨定），以及
已逃逸至固定定位的面板會像以下情況一樣，在祖先捲動時關閉
原生 select，而不是追逐（combobox）。同日：圖片獲得
透過彈出視窗處理連結＋lightbox（連結本身就是儲存的 DOM —
核心來源 href 從 figure > a 取得 — 而 lightbox 會使用 attrs
穿透），而焦點／大綱模式會顯示頂端列退出膠囊。

## Horizon 1 — 信任（0.6.x）：永遠不會有令人意外的行為

主題：加入的寫作者絕不能遺失工作，或遇到會讓他們
不信任這個介面。

- **貼上清理。** Word／Google Docs／任意 HTML 貼上 → 清理後的安全子集標記。
  ✅ *已於 2026-07-05 發布* — `sanitizePastedHtml()` + 插入游標內容（請參閱
  app.js 中的「貼上清理」區段，以及 `tests/paste.test.js`）。Word 的 mso-list 會重建為
  真正的巢狀清單；Docs 樣式 span 對應 strong／em／s／code；js: href、處理器及
  絕不會傳入廠商樣式；單次 ⌘Z 即可還原整個貼上操作。剪貼簿中的*影像*（檔案，
  不是 URL）隨下方的「行內媒體流程」項目上線。鏡像部分在
  v0.23.0：跨越多個島嶼的選取範圍會複製其實際區塊標記
  （`text/x-minimal-blocks`），貼回 Minimal（本文或其他文章）會重建
  區塊且設定保持完整；套件 `tests/island-copy.test.js`。
- **復原完整性。** 島嶼操作（插入、移除、表格操作）位於
  目前的瀏覽器復原堆疊。
  🔍 *已於 2026-07-05 調查*（實證、`scratchpad/undo-probe*.js`）。對應如下：
  - **execCommand 操作已完整追蹤** — 輸入、Markdown、工具列格式、豐富
    貼上（整個貼上會在一次 ⌘Z 中復原）、插入／移除圖片、建立／編輯連結。
  - **直接 DOM 操作不在堆疊中** — 插入島嶼（嵌入／圖庫／斜線自訂項目）、
    島嶼移除（退格防護／inspector）、表格列／欄／標題操作、inspector
    屬性重新生成。對所有這些情況，⌘Z 都是**安全的無操作**，絕不會造成損壞。
  - **核心標題：沒有任何序列會損壞。** 危險情況 — 原生復原輸入
    還原過時的完整 DOM 快照，會清除或重複未追蹤的 island —
    並不會發生**。Blink 的復原是以交易為基礎，而不是以快照為基礎：它會重播
    其 execCommands 記錄的特定範圍，並讓直接 DOM 節點保持不變。即使
    最糟糕的對抗案例（在表格儲存格中輸入，從使用者底下刪除該列
    待處理交易，然後按 ⌘Z）是乾淨的無操作，主控台完全沒有錯誤。
  - **唯一真正的缺口：結構性刪除無法復原。** 移除嵌入島嶼
    或表格列，而 ⌘Z 無法將其帶回（只有自動儲存／修訂／崩潰安全網
    可以做到粗略程度）。其他所有無操作都只是*不完整*，而非遺失資料。

  **決定：不要建立交錯的自訂復原日誌。** 因為沒有
  損壞，這是完整性／精修缺口，不是資料完整性問題 — 以及一份日誌
  能與 Blink 的原生堆疊正確交錯，代表要全域攔截 ⌘Z，並且
  基本上重新實作整個復原堆疊（也捕捉輸入，以維持順序
  右側）。這是針對潤飾功能的大型且脆弱的核心重寫 — 違反「不建置
  步驟／可 grep／islands 讓編輯器保持良好」的理念。改為：
  1. **島嶼刪除的提示復原**（移除嵌入／圖庫／自訂區塊）：Gmail 風格的
     「已刪除 — 復原」提示（約 7 秒），會重新插入移除的節點及其 islands[] 項目。
     ✅ *已於 2026-07-05 發布* — `toastAction()` + `removeIslandWithUndo()`；套件
     `tests/undo-toast.test.js`。自 2026-07-09 起，提示仍顯示時按 ⌘Z 也會執行
     復原（擷取階段 `pendingToastUndo`），因此鍵盤復原會與按鈕一致。
  2. **在真實復原堆疊上的表格操作**（2026-07-09）：新增／刪除列／欄、切換標題、
     以及表格刪除會修改分離的複製品，然後透過 `commandOnBlock`／交換
     `applyTableMutation`。圖表使用 `selectNodeContents`＋對內部內容執行 insertHTML
     標記（Blink 會巢狀插入完整 figure 的 `selectNode` insertHTML）；裸表格使用
     `selectNode`。表格刪除是對 figure 的內容刪除（⌘Z 會復原）。相同
     將圖片移除作為概念。破壞性操作會顯示「⌘Z 可復原」提示。套件：
     `tests/undo-toast.test.js` + `tests/table-menu.test.js`.
  3. **記錄邊界：** ⌘Z 涵蓋寫作＋表格結構＋移除圖片；
     島嶼刪除提供復原提示（提示顯示時也支援 ⌘Z）。剩餘的直接 DOM
     操作（inspector 屬性重新生成、島嶼插入）在 ⌘Z 下仍是安全的無操作。
     於 v0.24.0 重新驗證：pattern 與島嶼插入（`insertPatternIslands()`）以及
     inspector 屬性重新生成仍是直接 DOM 操作，並且仍是安全的無操作。
- **衝突安全性。** 文章鎖定／「其他人正在編輯」（核心的 heartbeat 鎖定），
  以及草稿的 localStorage 安全網，讓瀏覽器崩潰時即使在
  第一次自動儲存。
  ✅ *已於 2026-07-05 發布* — 鎖定功能採用核心本身的 `_edit_lock`
  （`minimal-admin/v1/posts/{id}/lock`；Minimal、classic 和 Gutenberg 彼此都能相互支援；
  接管對話框，30 秒重新整理同時作為接管偵測；唯讀並在以下情況顯示橫幅：
  已接管，發佈時會保留包括 `sendBeacon` 在內的內容（來自 pagehide）。崩潰防護網會擷取快照
  每次編輯都在約 1.2 秒內寫入 localStorage，下一次開啟時提供復原（包括
  從未儲存的新文章），成功儲存後會自行清除。套件：`tests/lock.test.js`，
  `tests/localnet.test.js`。這也提供了 Horizon 3 的 Presence 基礎。
- **輸入長尾。** IME／組字、行動版 Safari、無障礙。
  - **IME／組字（CJK）。** ✅ *已於 2026-07-12 上線* — 每條 keydown 路徑都
    `preventDefault` 的可列印按鍵，或攔截 Enter／Backspace 時會退出
    `isComposing`／keyCode 229：Markdown 包裝＋程式碼邊界跳脫、島嶼
    啟用中、斜線選單 Enter、figcaption Enter。真實 IME 引擎不在
    無頭 Chrome；`tests/ime.test.js` 會合成具有組字形狀的
    KeyboardEvents。
  - **行動版 Safari 檢查。** ✅ *已於 2026-07-12 上線* — `visualViewport` 寫入
    `--minimal-kb-inset`，因此固定底部介面（統計膠囊、提示）會位於
    軟體鍵盤；`viewport-fit=cover` + 安全區域內距；更大
    手機與粗略指標上的工具列／晶片／尋找命中目標；本文內距
    位於統計資訊膠囊下方；尋找輸入框為 16px（不會觸發 iOS 焦點縮放）。固定工具列
    保留 `-webkit-sticky`＋不透明背景。套件：`tests/mobile-editor.test.js`
    （手機視窗加模擬鍵盤插入區；不是真實的 iOS 裝置）。
  - **無障礙檢查。** ✅ *已於 2026-07-12 上線（初版）* — 格式
    工具列是 `role="toolbar"`，包含具標籤的工具；本文是多行
    文字方塊；island／table／image／code 晶片會攜帶 `aria-label`；斜線選單是
    listbox 搭配 `aria-activedescendant`；區塊彈出視窗（table／image／code／

    提示訊息是 `status`/`alert` 即時區域；鎖定接管是 `role="alert"`。
    套件：`tests/editor-a11y.test.js`。不是完整的 WCAG 稽核（沒有焦點陷阱
    環、不使用 axe CI」— 這些面向作者的操作便利功能。
- **行內媒體流程。** 從剪貼簿貼上／拖曳圖片，直接進入媒體
  游標所在處的庫；行內 figcaption 編輯。
  ✅ *已於 2026-07-05 發布* — 螢幕截圖 ⌘V 與拖放的圖片檔案會上傳至媒體庫

  既有競爭狀況：較晚的編輯器重新渲染可能在某次操作前還原未儲存的 DOM 編輯
  儲存（renderEditor 現在會在內容變更時採用即時 DOM）。

## Horizon 2 — 愉悅（0.7–0.9）：Gutenberg 永遠不會有的體驗

主題：只有在*寫作*工具中才有意義的功能，平靜的介面在其中
點。此範圍截至 v0.13.0 已封閉（寫入統計資料 + 斜線指令擴充
點是最後幾個項目）。

- **大綱面板。** ✅ *已於 2026-07-05 上線（v0.8.0）* — 標題目錄作為最後一個側邊欄
  卡片、固定；依統計節奏重建；點擊 ping 位於捲動區內
  內容座標。大綱*模式*（⌘⇧O）會折疊導覽及所有側邊欄卡片，除了
  大綱。套件：`tests/outline.test.js`。
- **專注模式。** ✅ *已於 2026-07-05 上線／zen 於 2026-07-06 上線* — 游標所在區塊的暗色帶、
  打字機捲動（限制即時步進；平滑捲動會被插入符號顯示取消），
  Zen 會收合導覽列與編輯器側邊欄。⌘⇧D 調色盤指令（不是工具列圖示）。套件：
  `tests/focus.test.js`.
- **修訂差異。** ✅ *已於 2026-07-05 上線（v0.8.0）* — 歷程卡片會開啟並排
  與目前 serializer 輸出的字數差異（計入未儲存的編輯）；使用具有 sameRatio 的 LCS
  閘門，讓不相關的新增／刪除段落保持分離。套件：`tests/revision-diff.test.js`。
- **內部連結選擇器。** ✅ *已於 2026-07-05 上線（v0.8.0）* — 連結彈出視窗的 URL 欄位
  會搜尋 `wp/v2/search` 中的非 URL 文字；選取後立即套用。測試套件：
  `tests/link-picker.test.js`.
- **尋找與取代** 文章內文字，支援 Markdown 感知。
  ✅ *已於 2026-07-10 發布* — ⌘⇧F（從 ⌘F 重新繫結，讓瀏覽器保留一般搜尋；另外還有一個
  ⌘K 指令）。比對會針對撰寫者看到的文字執行：每個區塊串接文字節點，因此一個
  比對會跨越行內標記（分割的 `<strong>`），但絕不跨越區塊邊界，而島嶼／
  `contenteditable=false` 子樹會被完全排除。高亮顯示是位於其中的疊加矩形
  內容座標上的捲動器（不會觸碰輸入表面）；取代選取
  比對 Range 並執行 `execCommand insertText`，因此每次取代都是原生的復原
  輸入，Replace-all 會由後往前套用，以保持較早的範圍有效。鎖定模式會
  一直到瀏覽器尋找。測試套件：`tests/find-replace.test.js`。
- **真正重要的寫作統計。** ✅ *已於 2026-07-12 上線（v0.13.0）* — 固定膠囊

## Horizon 3 — 編輯器即平台（1.0+）

- **Presence**（還有哪些人開啟這篇文章），以核心鎖定為基礎，而不是
  發明協作基礎設施。首批切片已上線：v0.19.0 週期
  關閉了鎖定故事最後的盲區（儲存會攜帶 `X-Minimal-Expect-Lock`
  標頭在伺服器端驗證，因此被移除的工作階段絕不會靜默覆寫；
  重新取得鎖定時會檢查伺服器的 modified stamp，並提供「載入對方版本」），
  以及 v0.20.0 內容清單顯示從核心讀取的「{name} 正在編輯」標籤
  自己的編輯鎖定。v0.21.0 強化了接縫：公開 REST 讀取不再揭露
  鎖定持有者的名稱（編輯訊號是給儀表板使用的，不是給全世界看的）。
  超越鎖定模型的即時游標／多人 Presence 仍是開放中的 1.0+ 項目
  問題；截至 v0.24.0，程式碼中不存在超越鎖定模型的任何功能。
- **可離線容錯的草稿功能**，前提是 Horizon 1 的 localStorage 網路證明可行。
  v0.24.0 仍待處理：尚未加入離線專用工作（app.js 沒有

## 我們永遠不會建置的功能（不變且承重）

**北極星：** Minimal 是 WordPress 的寫作編輯器。Gutenberg 是版面配置工具。
作者端契約請參閱 [content-blocks.md](content-blocks.md)。

永不實作：columns／groups／covers 作為即時版面畫布、pattern 或設計**製作**、
頁面建置、FSE、託管第三方區塊編輯器 JS、重新生成靜態 `save()` HTML、
或將「區塊 parity」作為 KPI。

可接受（不在永不實作清單中）：**插入**已完成的 pattern／設計庫標記作為
島嶼；編輯島嶼內的文字／圖片／屬性；發布**內容區塊**，其中
Minimal 完整編輯（動態且以 schema 為先）。

島嶼讓「不支援版面區塊」的成本變小 — 它能顯示、保存，並且
可透過伺服器允許的 inspector 進行設定。如果文章大多是版面配置，
Gutenberg 是正確的工具，而且交接只需點一下。這份清單維持編輯器
良好。

## 工程立場

- **保留無建置步驟。** 單一檔案，區段清楚分帶。如果編輯器加倍
  檔案，檔案大小會加倍 — 可搜尋性勝過此規模下的架構炫技。
- **測試套件是儲存庫公民**（自 2026-07-05 起完成）。Playwright 套件
  位於 `tests/` 中，共用輔助程式與慣例位於 `tests/README.md`；一個
  在 v0.18.0 之前，循序完整測試套件執行器讓全部 171 個測試套件通過，並且是其中一部分
  發布節奏；v0.24.0 的套件數維持在 206。編輯器錯誤修正
  仍會隨附移植後的測試套件。
- **安全模型已凍結。** `editorModeFor` → classic／blocks／locked，位元組一致性
  島嶼，以及必須能由 DOM 重現的屬性白名單。新能力擴充
  一次驗證一個屬性，逐步建立 allowlists（請參閱 editor-direction.md）；它們絕不會
  放寬模型。
