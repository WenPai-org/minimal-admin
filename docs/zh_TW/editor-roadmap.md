# 編輯器路線圖 — 長期計畫

*狀態最後於 2026-08-09 依據程式碼驗證（v0.26.0 週期，尚未發布）。
此計畫服務的可衡量目標位於 [roadmap.md](roadmap.md)；本文件記錄
編輯器論點、已發布帳冊，以及開放前沿。*

**論點：編輯器就是銷售功能。** Minimal Admin 起初是「更平靜的管理介面」，但
編輯器是產品成敗的關鍵。管理介面的其餘部分只是配角 —
優秀的配角，但沒有人會為了更好的外掛畫面而切換管理介面。人們
將工具切換至不同的「寫入位置」。

## 為什麼這是可行的

- **需求已獲證實且尚未被滿足。** Classic Editor 擁有五百萬以上的活躍
  在 Gutenberg 發布多年後才安裝 — 持續支持「不是區塊編輯器」的選擇，
  目前由凍結的技術提供。Minimal 是現代答案：流暢支援 Markdown、
  即時、平靜。
- **鎖定疑慮已解決，這就是護城河。** 每一個過去的「安心寫作」
  WordPress 編輯器死於兩種恐懼之一：*我的內容被困在你的格式中*
  或「*你的編輯器會摧毀我的版面*」。Minimal 儲存原生 Gutenberg 標記（開啟任一
  永遠編輯文章）以及區塊島嶼保留複雜版面
  位元組完全一致。沒有競爭者能講述這個故事；Gutenberg 本身也無法提供「平靜」
  其中一半。
- **寫作使用情境佔編輯的 90%——而自從巢狀週期開始，版面形狀
  其餘部分也會開放供寫作使用。** 段落、標題、清單、引文、程式碼、圖片、表格、
  嵌入內容，以及現在群組、欄、cover 和 media-text 內的文字。

## 定位

**「WordPress 的寫作編輯器。」** 不是「功能比
Gutenberg」— 不同工作使用不同工具。Gutenberg 是版面配置工具；Minimal 是
撰寫內容的地方；islands 和單鍵交接是兩者之間的接縫。
說「那是 Gutenberg 的工作」是策略，不是需要道歉的限制。

「可運作」的標準：**真實正式網站上的每篇文章都能被撰寫並
在 Minimal 中編輯，完全不必開啟區塊編輯器一次。**Dogfooding 是
路線圖的裁判——已在 [roadmap.md](roadmap.md) 中正式化為目標 1。

## 紙張割傷帳冊（工程知識，保留）

編輯器會以一千種細小行為接受評判，而 contenteditable 在每一項上都會反抗
一項。到目前為止的帳冊，全部已修復並通過回歸測試：Chrome 重新平衡空白
在行內邊界進行破壞性操作；`insertHTML` 將 `<code>` 重寫為樣式 span；
清單會巢狀於其來源段落內；整個區塊刪除會將相鄰項目合併到
殘留外殼；不可編輯的島嶼會因單次相鄰 Backspace 而消失；選取會消失
進入任何 modal；`execCommand('strikeThrough')` 會輸出過時標籤；對齊
透過 `justify*` 寫入樣式，而序列化器會將其剝除。**每項未來功能都會為
這類對抗**——瀏覽器層級的 Playwright 驗證迴圈並非可有可無
額外負擔，這正是編輯器贏得信任的方式。

兩項 Chrome 定位推論（2026-07-11）：任何必須視覺追蹤
可捲動內容位於捲動容器內的內容座標中（固定定位
每個捲動影格追蹤的 Chrome 會落後於合成器；ResizeObserver 會在實際
重排），而已逃逸至固定定位的面板會在祖先捲動時關閉
像原生選擇器一樣，而不是追逐（combobox）。

## Horizon 3——作為平台的編輯器（開放前沿）

- **Presence**（還有哪些人開啟這篇文章），以核心鎖定為基礎，而不是
  捏造協作基礎設施。截至目前已發布：鎖定故事的盲
  視窗已關閉（v0.19.0 `X-Minimal-Expect-Lock` 儲存驗證；「載入他們的」
  重新取得焦點時），內容清單會顯示「{name} 正在編輯」晶片（v0.20.0），而公開
  REST 讀取不會洩露持有者姓名（v0.21.0）。即時游標／多重在線狀態
  超出鎖定模型的部分仍是開放的 1.0+ 問題；鎖定模型以外沒有任何內容
  已存在於程式碼中。
- **可容忍離線的草稿**，前提是 localStorage 網路持續證明其可靠性。目前仍
  開放：app.js 不具備連線感知能力。防護網已有測試套件覆蓋
  （`localnet`），而過期 nonce 復原（v0.21.0）表示隔夜開啟的分頁仍可儲存
  無需重新載入即可。
- **行銷轉向。** FeiCode 儲存庫以編輯器為主：主視覺是寫作
  介面，而管理後台是「而且它周圍還有更好的管理後台」。已落地：
  FeiCode repository 是外掛列出的網站，提供可分享的文件頁面；readme.txt 是
  已消失。剩餘部分：由編輯器主導的 hero 本身；readme.md 仍以「重新構想的
  WordPress 管理後台體驗」，搭配總覽截圖，而不是寫作介面。

## 我們永遠不會建置的功能（不變且承重）

**北極星：** Minimal 是 WordPress 的寫作編輯器。Gutenberg 是版面配置工具。
作者端契約請參閱 [content-blocks.md](content-blocks.md)。

永不實作：columns／groups／covers 作為即時版面畫布、pattern 或設計**製作**、
頁面建置、FSE、託管第三方區塊編輯器 JS、重新生成靜態 `save()` HTML、
或將「區塊 parity」作為 KPI。

可接受（不在永不實作清單中）：**插入**已完成的 pattern／設計庫標記作為
島狀區塊；島狀區塊內的內容編輯文字／圖片／屬性（以及自巢狀週期開始，
直接在核心容器內寫入）；發布 **內容區塊**，讓 Minimal 編輯完全
（dynamic + schema-first）。

島嶼讓「不支援版面區塊」的成本變小 — 它能顯示、保存，並且
可透過伺服器允許的 inspector 進行設定。如果文章大多是版面配置，
Gutenberg 是正確的工具，而且交接只需點一下。這份清單維持編輯器
良好。

## 工程立場

- **保留無建置步驟。** 單一檔案，區段清楚分帶。如果編輯器加倍
  檔案，檔案大小會加倍 — 可搜尋性勝過此規模下的架構炫技。
- **測試套件是儲存庫的公民**（自 2026-07-05 起）。測試套件位於 `tests/`
  遵循 `tests/README.md` 中的慣例；循序完整測試套件執行器是
  發布節奏。編輯器錯誤修正仍會隨附移植後的測試套件發布。
- **安全模型已凍結。** `editorModeFor` → classic／blocks／locked，位元組一致性
  島嶼，以及必須能由 DOM 重現的屬性白名單。新能力擴充
  一次驗證一個屬性，逐步建立 allowlists（請參閱 editor-direction.md）；它們絕不會
  放寬模型。
- **體感是經過測量的，而非假設。** `tests/perf-editor.bench.js` 會回報每次按鍵
  跨越散文／巢狀／大型文件的延遲；在某個週期涉及
  編輯器渲染，並透過替換資產檔案與前一個標籤進行 A/B 測試（配方位於
  `tests/README.md`）。它產生的唯一硬性規則：**任何選擇器中不得有 `:has()`
  `#minimal-editor-body`** 中的比對結果——它會在每次
  按鍵（v0.26.0 晶片密度調整在巢狀頁面上測得每次按鍵約 300ms
  在它被重寫為事件集合標記類別之前）。
