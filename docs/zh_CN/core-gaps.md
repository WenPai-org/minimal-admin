## 优先级排名（重要缺口）

1. **术语管理** — ✅ 已发布 2026-07-10：**Terms** 管理器
   （Manage → Terms、`/minimal-admin/terms`）涵盖所有启用 REST 的分类法
   带有切换器、用于层级分类法的缩进树、内联
   创建/编辑（名称、别名、父级、描述），删除时提供诚实的
   确认，计数链接会进入经过筛选的内容列表，并且 **merge**
   （文章通过核心自身的重新分配机制移至保留的术语）
   机制，然后删除源文件）。编辑者通过
   `manage_categories`；每个分类法的权限由核心的
   REST 路由。
2. **媒体标题和描述** — ✅ 已发布（v0.11.0 周期）：媒体
   详情模态框现在可同时编辑标题、替代文本、标题和描述，
   携带编辑上下文的原始值（延迟获取，以保持列表
   浅色）并通过 wp/v2/media 保存。
3. **媒体批量选择/删除** — ✅ 已发布（v0.11.0 周期）：网格磁贴和
   列表行带有复选框（按住 Shift 选择范围、全选），并带有删除操作栏
   与内容列表模式一致；force=true，逐项处理。
4. **评论批量审核** — ✅ 已发布（v0.11.0 周期）：评论行获得
   复选框 + Select-page，以及一个操作栏，其动词取决于当前选项卡自身
   操作（Pending 中的 Approve/Spam/Trash，Trash 中的 Restore/Delete，以及
   上），按项目应用。
5. **批量更改用户角色** — ✅ 已发布（v0.11.0 周期）：用户表
   增加复选框列（以 edit-users 为门控）和一个可更改所有用户的操作栏
   一次性更改所选用户的角色；当前用户会被跳过（避免自我锁定
   守卫）。
6. **单篇文章格式选择器** — ✅ 已发布（v0.11.0 周期）：编辑器侧边栏
   具有 Format 选择器，前提是活动主题声明了 post-format
   支持（与 wp-admin 匹配），通过 wp/v2 的原生 `format` 保存
   字段。启动载荷携带受支持的格式。

## 按区域划分的状态

### Customizer 和主题选项 — 部分支持，主要是有意为之
已覆盖：站点身份位于 Settings → General（标题、副标题、站点图标
完整上传流程、站点地址、管理员邮箱）；主页设置位于
Settings → Reading（最新文章与静态页面，可选择页面）；截至
v0.11.0 周期，**Custom CSS**（`wp_custom_css_post`，Customizer 的
通过 Settings → Design 中的「Additional CSS」编辑
`minimal-admin/v1/custom-css`（edit_css 权限、每个主题的样式表、结构性
验证，与 Customizer 拒绝操作的行为一致）。自定义徽标和站点
语言已在 v0.20.0 周期发布（Settings → Site：徽标受控于
通过 `minimal-admin/v1/site-logo` 支持主题自定义徽标，语言
`minimal-admin/v1/site/language`，保存时下载数据包）。缺少：其他
主题 mod、FSE 全局样式。结论：身份信息 + 主页 + Custom CSS +
徽标 + 语言是日常所需，已经覆盖；真正的 Customizer
全局样式保持为长期尾部项目。

### Appearance — 在关键位置已覆盖
Menus（支持拖动排序）和经典小工具已完整构建；主题
在 Extensions 下安装/启用/更新/删除。模板/FSE 编辑，
背景图和页眉图：按设计不在范围内。

### 主题集成 — 已审计前沿（2026-07-30）
对于 CLASSIC 主题，日常所需已覆盖：Menus、Widgets、徽标、图标、
Custom CSS、首页。缺口集中在区块主题和主题构建器，
已在 v0.23.0 通过实证验证：

1. **没有替代方案时，区块主题会失去优势（L，需要设计）。**
   当 `wp_is_block_theme()` 时，Minimal 会正确隐藏 Menus 和 Widgets
   （`B.site.blockTheme`），但没有任何介入：没有导航编辑
   （`wp_navigation` 文章与 Menus 管理器中的内容具有 REST 对等性
   经典菜单已有的功能），没有模板/模板部件列表
   Site Editor 深层链接，没有全局样式摘要。区块主题站点
   使 Minimal 从「管理后台」降级为「内容管理后台」。范围明确的构建，
   在此项目中排序：导航优先（真实的日常工作、现有
   Menus UX 转移），然后是只读 Design 卡片（活动主题及其
   模板/部件显示为「在站点编辑器中编辑 ↗」行，以及当前调色板）。
   Site Editor 画布本身是永久外部链接（理由与
   表单构建器）。
2. **构建器主题模板不可见（M）。** `elementor_library` IS
   已暴露 REST，但未 `viewable`，因此内容切换器（正确地）
   会跳过它，这意味着页眉/页脚位于 Elementor Theme 中的站点
   构建器没有 Minimal 界面列出这些模板。同样适用于
   Bricks/Divi 模板区域。符合现有页面构建器适配器
   核心观点：列出并标注类型（页眉/页脚/弹窗/存档），显示
   显示条件为只读，并深层链接到构建器画布。
3. ~~**每个扩展的自动更新开关（S）。**~~ **已于 2026-08-04 发布**
   （v0.23.0 周期）：插件卡片和主题卡片均通过
   `minimal-admin/v1/auto-updates`（相同选项写入
   `wp_ajax_toggle_auto_updates`，清理过期条目；门控条件为
   `wp_is_auto_update_enabled_for_type`，服务器端和客户端）。Suite
   `tests/auto-updates.test.js`.
4. ~~**主题实时预览（S）。**~~ **已于 2026-08-04 发布**（v0.23.0
   周期）：非活动主题卡片上的实时预览链接：Customizer 用于
   经典主题上出现明显故障，区块主题使用 `site-editor.php?wp_theme_preview=`
   （`block` 标志现在通过 `minimal-admin/v1/themes` 传递）。
5. **超出状态的批量编辑（M）。** 内容批量操作栏支持状态/
   垃圾箱/恢复/删除，但不支持 wp-admin 批量编辑中的「添加这些
   在所选文章中设置分类/作者」。
6. ~~**同步模式（S-M）。**~~ **已于 2026-08-04 发布**（v0.23.0 周期）：
   wp_block 通过可查看门槛加入允许列表（`slimContentTypes`）→ 一个
   Content 切换器中的 Patterns 入口，使用标准行机制
   （前端查看/预览被抑制，不可公开查询）；斜杠
   菜单 + ⌘/ 选择器「Your patterns」（已同步 → `wp:block {"ref":N}`
   参考岛、静默插入；未同步 → 通过
   `insertPatternIslands`）；编辑器会原生打开 `/editor/blocks/{id}`
   带有同步编辑提示和自动精简的侧边栏；+ New → Pattern。
   注意：`wp_pattern_sync_status` 在 REST 中是顶层只读字段；
   写入通过 `meta.wp_pattern_sync_status` 完成。套件
   `tests/user-patterns.test.js`.
7. **经典 Customizer 主题选项 — 保持为外部链接。** 任意
   主题 mod（颜色、页眉/背景图像、每个主题的章节）是
   没有架构的逐主题反复适配；Customizer 深层链接是
   诚实的答案，与之前结论相同。

### Taxonomies — 已覆盖
Terms 管理器已于 2026-07-10 发布（见优先级 #1）。唯一的服务器
新增内容是 `minimal-admin/v1/terms/merge`；其他全部使用核心 REST。
从 v0.11.0 周期开始，Terms 已并入 **Structure** 页面（Post
Types / Taxonomies / Terms 选项卡，而不是独立导航项，以保持
MANAGE 组显得不完整。各标签单独控制：Post Types 和
分类法需要 `manage_options`，Terms 只需要 `manage_categories`，因此
编辑器的 Structure 项目只显示 Terms 选项卡（标记为「Terms」，用于
它们），而管理员可以看到全部三个。`/minimal-admin/terms` 路由以及
⌘K「管理分类和标签」命令仍然有效，并进入 Terms 标签页。

### Tools — System 页面功能强大，但缺少一次性工具
System 页面完善覆盖诊断功能（健康检查、数据库表、自动加载
权重、cron 健康状态、调试开关和日志查看器、集成注册表、
扩展清单、复制为 Markdown 的报告）。Loopback 和 REST 自检
健康状态行已于 2026-07-10 发布（核心自身的 Site Health 测试，缓存 15
分钟），Tools 卡片深层链接到一次性任务（Site Health、
导出/导入、GDPR 导出/擦除）：偶发性操作仍保留在 wp-admin 中，一个
点击离开，按设计如此。截至 v0.22.0 周期，Database 卡片也成为
入口：其最大表格的行以及「browse all」链接会打开只读
数据库查看器（`/minimal-admin/database`，也可通过 ⌘K 访问；有意不作为导航
项目）。写入操作和 SQL 控制台在此处始终不在目标范围内
(`native-editors.md`).

### Settings — 日常选项已覆盖，两个屏幕较薄弱
今天可写入：General（标题、副标题、图标、URL、管理员邮箱、时区、
日期/时间格式、每周起始日、默认角色、成员资格、维护、默认
admin）、Writing（默认分类/格式、表情符号）、Reading（首页、
每页文章数、搜索可见性）、Discussion（默认评论/引用状态、
审核、必须注册、头像开关），Permalinks（结构 +
基础）、Spam（提供商卡片 + 禁止的键）、Connectors（WP 7.0 的
连接器注册表：提供商键由核心端进行遮蔽和验证，
对于 wp-config/env 键保持来源诚实，配套插件安装位于
位置），此外自 v0.20.0 起，Site 标签页还包含站点徽标和站点语言
周期。缺少：整个 Media
设置屏幕（缩略图尺寸、月份/年份文件夹），
`posts_per_rss` / feed 摘要，以及大部分 Discussion 矩阵（线程
深度、每页数量、之前批准的快捷方式、关闭后天数、通知
电子邮件、头像评级/默认值）。判断：缺少的是一次性配置；
只有评论较多的网站提出需求时，才增加 Discussion 深度。

### Users — 达到或优于对等水平
列表、搜索、角色、添加/编辑、删除并重新分配内容、密码
重置、发送邮件、终止会话、批量更改角色（v0.11.0 已发布），
应用程序密码（「AI Access」，附带生成的代理指南）。
所有长期尾部个人资料字段已于 v0.17.0 在 /minimal-admin/profile 发布
页面（名、姓、个人简介、网站、每个用户的语言，并自动
包安装、前端工具栏偏好）。应用程序密码
比经典界面更清晰地呈现，并支持删除时重新分配。

### Media — 网格功能完善，编辑功能已跟上
支持类型筛选/搜索/分页的网格、多文件上传、拖放、图像
编辑器（旋转/裁剪为新副本）、特色图像流程、删除、复制 URL、
标题/描述编辑和批量删除（均已在 v0.11.0 发布）。
未附加筛选器（核心 parent=0）、月份筛选器（minimal-admin/v1/media/months
组合框 → 前后时间窗口）以及详情模态框中的「Attached to」行
带编辑器跳转的功能已于 2026-07-17 全部发布（v0.18.0 周期，套件
media-polish）。文件夹：不是
核心功能（Minimal 自有的树会成为不可见的第五种文件夹标准
到 wp-admin 和构建器选择器），但此前「长尾、跳过」的结论
已于 2026-07-16 修订：FileBird + Real Media Library + Folders 总计超过 400k
安装后，优先浏览的提供商契约成为 Wave D 的一部分
`docs/plugin-support.md`。Wave D 已于 2026-07-17 发布（v0.18.0 周期）：
`minimal_admin_media_folders` 提供商筛选器
（`includes/adapters/media-folders.php`），但没有介入：没有导航编辑
由 Premio 提供商提供的媒体库和文件夹；Media 视图中的文件夹选择器
会筛选普通的 wp/v2/media 查询（搜索、类型选项卡、未附加和
分页继续有效，每个文件夹最新 500 项），以及「移动到文件夹」批量
操作调用每个提供商可选的 `move`；Suite
`tests/media-folders.test.js`。移动操作仍以浏览为先：Minimal 永不拥有
自己的文件夹树。

### Comments — 完整支持单行和批量操作
待审核/已批准/垃圾邮件/回收站选项卡，完整的逐行审核，批量
审核，并按选项卡提供操作动词（已在 v0.11.0 发布），支持内联回复
（像核心一样自动批准）、上下文菜单。最后两个缺口已在
v0.20.0 周期：内联评论编辑（文本始终支持；作者姓名/邮箱支持
访客评论）和 Block commenter（将作者的电子邮件或 IP 添加到
核心的禁止列表，在 Settings → Comments 下可见，并支持 Undo）。

### Multisite — 非目标，但会合理降级
存在防御性门控（`manage_network_users`、超级管理员文件修改
检查、System 报告行）。无网络界面，也不会在
子站点。

### 结构性观察 — 仅 REST 是硬边界
任何未暴露给 REST 的内容，根据设计对 Minimal 不可见：CPT 和
不带 `show_in_rest` 的分类法（UI 会标记它们）、未注册的元数据、
自定义状态。这是有意为之，值得保留；这条界线
让列表视图保持快速且安全。
