# v1.0 就绪——审计与 v0.17.0 章程

*撰写于 2026-07-16、v0.16.0 时期，基于对插件、面向作者的
文档（包括由项目新人进行的初读），以及路线图
文档。这是 v0.17.0 周期的工作章程。*

v1.0 的门槛不在于功能数量，而在于 Minimal 必须能够兑现的两个承诺
大声说出来：

1. **插件作者喜欢接入。** 一名合格的 WordPress 开发者可以将其
   在一个下午内将插件接入 Minimal，无需阅读 Minimal 的源代码，并且知道
   契约不会在这些变化下失效。
2. **插件作者无法滥用 Minimal。** 插件注册的任何内容都无法抢占
   用户未要求的注意力，而插件注册的所有内容都可能
   被用户静音。WordPress 在其通知系统中输掉了这场较量；Minimal
   必须通过架构和用户控制权赢得这场胜利，而不是依靠政策文档。

## 已经正常工作的内容（保留，并大声强调）

- **架构本身具备抗滥用能力。** 第三方 PHP 永远不会钩入
  进入 Minimal 的渲染路径，第三方 HTML/CSS/JS 永远不会到达 SPA。
  集成是纯数据描述符；Minimal 会在边界处转义每个值。
  整类 wp-admin 滥用（任意管理员 HTML、巨型横幅、伪装的
  按钮）在这里不存在。这是目标 #5，并且已经满足。
- **通知已经解决。** 插件无法向 Minimal 的任何内容注入
  通知面板。他们的 wp-admin 通知仅通过提取到达：
  简化为文本、严重性和最多三个链接，并归属于其所有者，
  用户可通过撤销操作隐藏，操作链接在后台运行。这
  正是 WordPress 通知问题的答案，应当成为一个
  标题级声明，而不是变更日志脚注。
- **快速入门的投入产出比。** 二十行声明式代码即可生成分页的
  可搜索、按能力门控的管理视图，无 JavaScript 且无需构建步骤。
- **Integrations 卡片。** 一个实时注册表，列出所有已注册内容，并标明
  按插件处理，并标记契约问题，而不是静默失败。大多数
  生态系统永远不会构建这个。
- **书面的兼容性承诺**（仅新增、弃用窗口、「键
  不在此页面上是内部的」），并引用真正
  可读。五十多个捆绑适配器证明这些原语可跨越不同场景通用
  四种不同的设置架构框架。
- **质量标准**：约 150 个浏览器测试套件，在干净的和
  生产规模的网站，零控制台错误门槛。

以下项目在 v0.17.0 周期内发布；门槛注释进一步
向下补充细节。简而言之：1 个以快速入门为先的重构，2
extension-api.md 已删除，3 个垫片教程 + 测试套件强制执行的示例插件，
4 个已记录的能力模式，5 个原语截图，6 个规范
图标列表，7 所有缺失的基础内容以及测试你的适配器章节，8
每个用户都可隐藏每个集成点，强制执行 9 个注意力预算，

### 作者体验

1. **快速入门被埋得太深。** for-plugin-authors.md 以一个 19 行的 hook 表开头
   表格、文件约定和兼容性部分，然后再取得第一项成果。
   初次使用者要先浏览 `minimal_admin_visibility_providers`，然后才能看到
   他们需要的唯一筛选条件。
2. **extension-api.md 是个陷阱。** 它是最初的提案文档，标题仍为
   "(proposal)"，仍从 readme 链接到它，其示例使用的按键确实
   不存在于已发布的词汇中（`stats`，一种旧的 `tabs` 形态）。两个
   冲突的描述符方言，没有横幅。
3. **自定义表路径没有教程。** 大多数表单/日志插件会将数据存储在
   自定义表。文档的答案是「阅读 Gravity SMTP 适配器」。该垫片
   是多数情况，值得进行带注释的演练，而不是源代码
   指针。
4. **cap 语义分散在各处，参考适配器却教导了另一套
   模式，而不是文档**（界面 `cap: 'read'` 加上适配器侧门控，
   GF 先例，但未记录）。
5. **没有截图。** 作者选择 `format` 值、详细 `kind`s 和状态
   布局中盲目进行。
6. **图标说明不一致。** 文档列出了 11 个图标名称；捆绑的适配器使用
   不在列表中的名称；编辑器命令描述了第三种词汇。
7. **缺少基础信息**：每个键的必需/可选标注、引入版本注释、
   国际化指南、`manage` 与 `views` 的区别、`group` 值列表，以及一个
   "test your adapter" 部分（Playground 蓝图已经存在，但作者
   指南从未提到它）。

### 抗滥用能力

8. **没有用户覆盖选项。** 用户无法隐藏或静音插件的界面、编辑器
   面板、调色板条目或斜杠命令。用户主权是
   其他所有控制的后备机制，而它目前还不存在。
9. **没有位置或数量预算。** 任意插件都可以声明 `group: 'workspace'`，
   注册任意数量的界面，并在 ⌘K 调色板中加入无限条目
   （每个界面都会成为一个由插件控制标签的调色板行），并将
   默认斜杠菜单中的条目。「工作区用于收件箱形态」
   该规则只是有文档记录的约定，未在任何地方强制执行。
10. **外部链接未统一标记。** 描述符 `href` 操作以及
    状态卡片链接可以携带任意 URL；某些渲染界面会添加 ↗，但这并非
    保证，因此行操作可能会悄悄变成追加销售链接。
11. **没有明确且有后果的使用规范。** 文档从未说明对
    提供促销标签或催促式界面的集成。

## v0.17.0——插件作者周期（拟议范围）

两条方向都服务于上述门槛。

### 方向 A：作者体验

- **文档重构**（G6）：先介绍快速入门；将 hooks 表降级为
  参考部分；拆分过长的表格单元格；记录 `manage` 与 `views` 的区别，
  `group` 词汇、上限模式（包括适配器侧门控
  先例作为一等文档化模式）、必需与可选，以及
  按版本添加。添加规范图标列表（由 `icon()` 映射生成
  因此不会发生漂移）。
- **shim 教程**（G1）：带注释的演练，构建一个用于
  虚构 custom-table 插件，从头到尾完成，最终到达 Integrations
  显示绿色状态的卡片。将完成的示例作为一个真实的小型插件发布
  (`docs/examples/` 或单独的仓库），供作者复制，然后将其添加到
  Playground 蓝图，因此「试用 API」只需单击一次。
- **截图** 展示每个原语（界面列表、详细信息类型、状态卡片、
  设置门槛、设置视图、编辑器面板、斜杠条目）均以相同方式捕获
  营销截图就是这样。
- ~~**forms 系列配套内容**~~ *(已于 2026-07-16 发布，与
  要求重新审查：「让你的表单插件成为一等
  Forms provider" 部分——包含每个表单动态标签页的完整描述符，
  `entry-summary` 语义、条目类型的主视觉/正文启发式规则、`manage`、
  `family` 共存、`href` 导出模式——以及其中的小要点
  它们自然的归属位置：DELETE 操作、列可排序性说明、`WP_Error`
  创建时、旧版 Minimal 的降级行为、`detail.labels` 响应形态。）*
- **终结 extension-api.md 陷阱**：顶部的历史横幅指向
  for-plugin-authors.md（已在本周期的审计提交中完成），然后合并
  仍然有用的理由纳入作者指南，并删除该文件。
- **面向代理的创作**：一个简短的「将此交给你的编码代理」部分
  （或 AGENTS.md）——作者越来越多地使用 AI 工具接入集成，而
  描述符契约特别适合这一点。

### 方向 B：滥用防护

- **隐藏任何集成**（G2）：针对界面的按用户隐藏（导航右键菜单和
  集成卡片上的控件）、编辑器面板、插件的调色板
  条目和斜杠命名空间。交互形态与通知 Hide 相同（用户元数据、
  撤销提示，在重新注册后仍然存在）。
- **注意力预算**（G3）：在 `Minimal_Admin_Surfaces` 和客户端中强制执行——
  工作区放置需要一个收件箱形状的集合（验证器规则）；
  对默认斜杠条目和调色板行设置每插件上限，并自动
  降级为仅搜索；同一所有者超过 N 个界面时会合并为
  一个导航项，并沿用现有的系列切换器机制。
- **外部链接提示保证**（G4）：所有界面使用一个共享渲染器
  描述符 href；站外链接始终显示 ↗ 并在新标签页中打开；
  验证器会标记站外 href，因此 Integrations 卡片会显示这些链接。
- ~~**Integration etiquette 部分**~~ *(已于 2026-07-16 发布：作者指南的
  "Integration etiquette" 部分完整说明了整个执行机制——
  验证器阻止或降级的内容，该渲染属于 Minimal，用户可以隐藏哪些内容——
  以及「标签用于命名，而非营销」的直白声明。）*
