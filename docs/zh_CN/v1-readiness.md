# v1.0 charter

*The two promises a v1.0 has to make, and the gates that decide when it can.
Written 2026-07-16 at v0.16.0 from a full audit of the plugin and its docs; the
audit's own findings and the cycle that cleared them have been folded into
[changelog.md](../changelog.md) rather than kept here. Forward-looking work lives
in [roadmap.md](roadmap.md).*

v1.0 的门槛不在于功能数量，而在于 Minimal 必须能够兑现的两个承诺
大声说出来：

1. **插件作者喜欢接入。** 一名合格的 WordPress 开发者可以将其
   在一个下午内将插件接入 Minimal，无需阅读 Minimal 的源代码，并且知道
   契约不会在这些变化下失效。
2. **插件作者无法滥用 Minimal。** 插件注册的任何内容都无法抢占
   用户未要求的注意力，而插件注册的所有内容都可能
   被用户静音。WordPress 在其通知系统中输掉了这场较量；Minimal
   必须通过架构和用户控制权赢得这场胜利，而不是依靠政策文档。

## 已经正常工作的内容（保留，并大声强调）

- **架构本身具备抗滥用能力。** 第三方 PHP 永远不会钩入
  进入 Minimal 的渲染路径，第三方 HTML/CSS/JS 永远不会到达 SPA。
  集成是纯数据描述符；Minimal 会在边界处转义每个值。
  整类 wp-admin 滥用（任意管理员 HTML、巨型横幅、伪装的
  按钮）在这里不存在。这是目标 #5，并且已经满足。
- **通知已经解决。** 插件无法向 Minimal 的任何内容注入
  通知面板。他们的 wp-admin 通知仅通过提取到达：
  简化为文本、严重性和最多三个链接，并归属于其所有者，
  用户可通过撤销操作隐藏，操作链接在后台运行。这
  正是 WordPress 通知问题的答案，应当成为一个
  标题级声明，而不是变更日志脚注。
- **快速入门的投入产出比。** 二十行声明式代码即可生成分页的
  可搜索、按能力门控的管理视图，无 JavaScript 且无需构建步骤。
- **Integrations 卡片。** 一个实时注册表，列出所有已注册内容，并标明
  按插件处理，并标记契约问题，而不是静默失败。大多数
  生态系统永远不会构建这个。
- **书面的兼容性承诺**（仅新增、弃用窗口、「键
  不在此页面上是内部的」），并引用真正
  可读。五十多个捆绑适配器证明这些原语可跨越不同场景通用
  四种不同的设置架构框架。
- **质量标准**：约 150 个浏览器测试套件，在干净的和
  生产规模的网站，零控制台错误门槛。

## v1.0 门槛

*2026-08-06 状态检查（树中为 v0.24.0，尚未发布；v0.23.0 已发布
2026-08-04）：G2 到 G6 仍已在 v0.24.0 中发布并由测试套件覆盖
（tests/hide-integrations.test.js、hide-slash-designs.test.js，
design-sources.test.js、attention-budgets.test.js、offsite-links.test.js、
contract.test.js 加上 example-adapter.test.js；名册已从
审计时约 150 个套件增至 206 个）。自上次检查以来的周期（
数据库查看器、可见性切换、每个扩展的自动更新
标签、同步模式、i18n、捆绑的用户指南、经过校验和验证的
更新、WPForms 条目）没有在
受条件控制的词汇；自 v0.22.0 以来唯一新的扩展点，
`minimal_admin_visibility_toggles` 是服务器端写入器回调，而不是
UI 放置。G1，即与真实外部测试者进行的下午测试，仍然
唯一的开放门槛。其材料全部就绪（docs/shim-tutorial.md，
套件强制使用的 docs/examples/minimal-example-adapter、Playground
蓝图）；找到该测试者仍是排期工作，而不是工程工作
工作。*

v1.0 在满足以下所有条件时发布：

- [ ] **G1 — 下午测试。** 一名从未见过 Minimal 的开发者接入一个
      自定义表插件扩展为完整界面（列表、详情、操作、状态
      卡片），仅使用文档，在不到半天内完成。已由真实的
      外部测试人员，而不仅仅是在内部。
- [x] **G2 — 用户主权。** 每个已注册的集成点（界面、
      面板、命令、设计来源）可由用户在界面中单独隐藏，并且
      隐藏设置在更新后仍然保留。*（界面 + 编辑器面板已于 2026-07-16 发布，
      v0.17.0 周期：`minimal_admin_hidden_integrations` 用户元数据，
      `minimal-admin/v1/integrations/hide|unhide`、导航/入口右键、恢复
      在 Your profile 中。设计来源（`design:<id>`）和斜杠命名空间
      (`slash:<ns>`，涵盖自动区块 + 插入模板 + 模式 +
      将命名空间命令放在一起）在当天晚些时候完成了门槛：
      右键点击区块选择器的分组标题；隐藏的条目会离开
      服务器负载，并在原地裁剪内联斜杠菜单。调色板行
      沿用其界面的隐藏设置。）*
- [x] **G3 — 注意力预算。** 放置位置和数量限制由
      验证器和客户端，而不是依靠约定。插件不能添加超过
      将其预算分配给导航、调色板或默认斜杠菜单；溢出时降级
      平稳降级（仅搜索、折叠分组），而不是直接丢弃。
      *（已于 2026-07-16 发布，v0.17.0 周期。Workspace 要求一个类似收件箱的
      集合（一个 `ago` 列），否则会降级为带验证器的 Tools
      标记。一个所有者最多持有 3 个导航槽位：超过后，没有所属系列的
      界面合并为一个合成系列（一个导航项、一个调色板
      行，以及现有的切换器机制；Minimal 的捆绑适配器免于此规则，因为
      每个仅在其目标插件处于活动状态时注册，而 Unknown
      所有者豁免，因此归属失败绝不会合并陌生人）。一个
      命名空间最多容纳 3 个默认斜杠条目；超出的条目降级为
      仅搜索。Integrations 卡片会标记工作区问题并
      以信息方式提示超出预算的所有者。）*
- [x] **G4 — 外部链接诚实性。** 每个插件提供的、离开
      网站都会使用外部链接提示。任何描述符都无法使一个
      让追加销售看起来像应用操作。*（已于 2026-07-16 发布，v0.17.0 周期：
      共享的 `hrefLabel()` 渲染器在每次渲染时为站外 href 标记 ↗
      网站（状态卡片操作、详情模态框操作、行菜单以及每个
      openMinimalMenu 链接），验证器会列出由描述符携带的
      每个界面上的站外 href，位于 Integrations 卡片中，以信息方式展示。
      状态卡片链接会在运行时随路由响应返回，因此它们会获得
      渲染时标记，但没有静态标志。作者指南的
      Integration etiquette 部分说明了这一保证。）*
- [x] **G5 — 契约冻结。** 文档中描述的描述符词汇已完整
      （不存在未记录且承担关键作用的键），注明引入版本，并且
      由一套契约测试覆盖，该测试驱动一个第三方插件夹具
      贯穿每个文档化键。*（已于 2026-07-16 发布，v0.17.0 周期：
      tests/contract.test.js，共 36 项检查。一半之一是 DOC LOCKSTEP——每个
      验证器词汇常量中的键必须出现在
      for-plugin-authors.md，因此新键无法在未记录的情况下加入。后半部分
      驱动 minimal_test_contract_surface 这个覆盖全部场景的夹具（路由
      选项卡 + allRoute、query/pageQuery、每种列格式 + altKey/utc/
      宽度、使用 label/messageKey/skip/edit + preserve 以及完整的
      字段词汇、每个操作键、受条件控制的批量、筛选、创建
      使用默认值、管理、views[]、状态行/图表/命令/操作，
      通过 settingsItem 实现条目级设置）端到端配合服务器状态
      验证；同一个描述符在以下情况下验证结果为 ZERO 问题：
      Integrations 卡片本身就是一项契约检查。设置门槛、纯
      设置视图、编辑器面板和设计来源均由其各自的
      各自专用的 fixture 测试套件。）*
- [x] **G6 — 一个文档入口。** 单一作者指南从
      快速入门包含 shim 教程和截图，并且没有过时的
      因为没有与之矛盾的同级内容。*（重构已于 2026-07-16 发布：快速入门
      快速入门优先、垫片教程 + 测试套件强制执行的示例插件、测试你的适配器
      以及 AI 代理章节、已记录的能力模式、规范图标
      列表、拆分连写单元格、since-versions、删除 extension-api.md。
      截图于当天稍晚完成：九张深色主题 2x 截图位于
      docs/img，涵盖每个原语（界面列表、状态卡片、详情
      模态框、联系卡片条目、设置门槛、设置视图、侧边栏入口 +
      打开的面板、斜杠命名空间条目），使用实时应用捕获
      以 Campfire 示例适配器为主题，使教程及其
      图片不能出现偏差；营销网站的指南模态框会渲染它们
      通过 GitHub raw。）*
