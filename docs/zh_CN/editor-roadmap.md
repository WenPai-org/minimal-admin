# 编辑器路线图 — 长期计划

*状态最后根据 v0.24.0（未发布）代码于 2026-08-06 验证。*

**论点：编辑器就是销售功能。** Minimal Admin 起初是「更平静的管理后台」，但
编辑器决定产品成败。管理后台的其余部分只是配角 —
出色的配角，但没人会为了更好看的插件页面而切换管理后台。人们
根据*写入位置*切换工具。

## 为什么这很现实

- **需求已得到验证但尚未满足。** Classic Editor 拥有五百万以上活跃
  在 Gutenberg 发布多年后仍有人安装 — 这是对「不要区块编辑器」的持续支持，
  目前由冻结的技术提供支持。Minimal 是现代答案：精通 Markdown、
  即时、平静。
- **锁定顾虑已解决，这就是护城河。** 每个此前的「安心写作」
  WordPress 编辑器曾因两种担忧之一而消亡：*我的内容被困在你的格式中*
  或*你的编辑器会破坏我的布局*。Minimal 存储原生 Gutenberg 标记（打开任意
  文章在区块编辑器中，随时、永久）以及区块岛保留复杂布局
  字节级一致。没有竞争者拥有这种说法；Gutenberg 本身也无法提供「平静的」
  其中一半。
- **写作场景占编辑操作的 90%。** 段落、标题、列表、引文、代码、
  图片、偶尔的表格和嵌入。Minimal 的编辑器已经全部支持，并且
  Markdown 约定、可用的撤销，以及采用网站真实样式的预览。

## 定位

**「WordPress 的写作编辑器。」** 而不是「一个功能比……更少的编辑器」。
Gutenberg」 — 不同工作使用不同工具。Gutenberg 是布局工具；Minimal 是
写作发生的地方；islands 和一键交接是连接两者的缝合线。
说「那是 Gutenberg 的工作」是策略，而不是需要道歉的限制。

「它能工作」的标准：**真实生产站点上的每篇文章都能被编写并
在 Minimal 中完整编辑，无需打开区块编辑器一次。**Dogfooding 是
路线图的裁判。

## 构建 v0.5.x 学到的经验（细节问题账本）

编辑器要经受上千种细微行为的检验，而 contenteditable 在每一种行为上都在反抗
一项。到目前为止的账本，全部已修复并通过回归测试：Chrome 会重新平衡空白
在内联边界处进行破坏性处理；`insertHTML` 将 `<code>` 重写为带样式的 span；
列表嵌套在其源段落中；整区块删除会将相邻内容合并为
残余外壳；不可编辑的岛通过一次相邻 Backspace 消失；选择消失
进入任何模态框；`execCommand('strikeThrough')` 会生成过时标签；对齐
通过 `justify*` 写入的样式会被序列化器剥离。**每个未来功能都要为
这一类争斗**——浏览器级别的 Playwright 验证循环不是可选项
额外开销，这是编辑器赢得信任的方式。

2026-07-11 又有两条 Chrome 定位推论加入记录：任何
必须在视觉上跟随滚动内容的元素位于滚动容器内部，位置为
内容坐标（每个滚动帧追踪固定定位的 Chrome 会落后于
合成器和弹性过度滚动报告在稳定前不会返回任何内容 —
区块标签片段抖动；ResizeObserver 会在真实重排时重新锚定），以及
已经逃逸到固定定位的面板，会像这样在祖先滚动时关闭
原生选择框，而不是追逐（combobox）。同一天：图片获得了
通过弹出层处理链接 + 灯箱（链接本身就是保存的 DOM —
来自 figure > a 的核心来源 href — 而灯箱会使用这些属性
直通），焦点/大纲模式会显示顶部栏退出标签。

## Horizon 1 — 信任（0.6.x）：永远没有令人意外的行为

主题是：写作者加入后绝不能丢失工作，也不能遇到让他们
不信任这个界面。

- **粘贴清理。** Word / Google Docs / 任意 HTML 粘贴 → 干净的安全子集标记。
  ✅ *已于 2026-07-05 发布* — `sanitizePastedHtml()` + 插入符上下文插入（参见
  app.js 中的「粘贴清理」部分和 `tests/paste.test.js`）。Word 的 mso-lists 会重建为
  真正的嵌套列表；Docs 样式 span 映射到 strong/em/s/code；js: href、处理程序和
  供应商样式永远不会通过；单次 ⌘Z 会撤销整个粘贴操作。剪贴板中的*图像*（文件、
  而不是 URL）已随下面的「内联媒体流程」条目发布。镜像部分在
  v0.23.0：跨越多个岛状区域的选择会复制其真实的区块标记
  （`text/x-minimal-blocks`），然后粘贴回 Minimal（本文或其他文章）会重建
  区块且设置保持完整；套件 `tests/island-copy.test.js`。
- **撤销完整性。** 岛操作（插入、移除、表格操作）位于
  当前的浏览器撤销堆栈。
  🔍 *已于 2026-07-05 调查*（实证，`scratchpad/undo-probe*.js`）。映射如下：
  - **execCommand 操作均已完整追踪** — 输入、Markdown、工具栏格式化、富
    粘贴（整次粘贴可通过一次 ⌘Z 恢复）、图片插入/移除、链接创建/编辑。
  - **直接 DOM 操作不在堆栈中** — 岛插入（嵌入/图库/斜杠自定义）、
    岛移除（退格保护 / 检查器）、表格行/列/表头操作、检查器
    属性重新生成。对于所有这些情况，⌘Z 都是**安全的空操作**，绝不会造成损坏。
  - **核心结论：不会出现序列损坏。** 危险情况 — 对输入内容执行原生撤销
    恢复过时的完整 DOM 快照，这会清除或复制未跟踪的岛屿 —
    不会发生。Blink 的撤销基于事务而不是快照：它会重放
    其 execCommands 记录的特定范围，并让直接 DOM 节点保持不变。即使
    最恶劣的对抗性情况（在表格单元格中输入，从正在编辑的
    待处理事务，然后 ⌘Z）是干净的空操作，不产生任何控制台错误。
  - **唯一真正的缺口：结构性删除无法恢复。** 移除一个嵌入岛
    或表格行，而 ⌘Z 无法将其恢复（只有自动保存 / 修订 / 崩溃安全网
    可以，粗略地）。其他所有空操作都只是*不完整*，而不是有损。

  **决定：不要构建交错式自定义撤销日志。** 因为不存在
  损坏，这是完整性/润色缺口，而不是数据完整性问题 — 以及一个日志
  能够正确地与 Blink 的原生堆栈交错，这意味着要全局拦截 ⌘Z，并且
  本质上重新实现整个撤销堆栈（也捕获输入，以保持顺序
  右）。这是为润色功能进行的大规模且脆弱的核心重写 — 与「无构建
  步骤化 / 可 grep / 岛屿让编辑器保持良好」的理念。相反：
  1. **岛删除的 Toast-Undo**（嵌入/图库/自定义区块删除）：类似 Gmail 的
     「已删除 — 撤销」提示（约 7 秒），会重新插入被移除的节点及其 islands[] 条目。
     ✅ *已于 2026-07-05 发布* — `toastAction()` + `removeIslandWithUndo()`；套件
     `tests/undo-toast.test.js`。自 2026-07-09 起，提示仍显示时按下 ⌘Z 也会执行
     恢复（捕获阶段 `pendingToastUndo`），因此键盘撤销与按钮操作一致。
  2. **真实撤销堆栈上的表格操作**（2026-07-09）：添加/删除行列、切换表头、
     而表格删除会修改分离的克隆，然后通过 `commandOnBlock` / 交换
     `applyTableMutation`。图使用 `selectNodeContents` + 对内部内容执行 insertHTML
     标记（Blink 会嵌套完整 figure 的 `selectNode` insertHTML）；裸表格使用
     `selectNode`。表格删除操作的是 figure 的内容（⌘Z 可恢复）。同样
     将图片移除作为创意。破坏性操作会提示「⌘Z 可恢复」。套件：
     `tests/undo-toast.test.js` + `tests/table-menu.test.js`.
  3. **记录边界：** ⌘Z 覆盖写作 + 表格结构 + 图片删除；
     岛删除提供撤销提示（提示显示时也支持 ⌘Z）。剩余的直接 DOM
     操作（检查器属性重新生成、岛插入）在 ⌘Z 下仍然是安全的空操作。
     在 v0.24.0 重新验证：模式和岛插入（`insertPatternIslands()`）以及
     检查器属性重新生成仍然是直接 DOM 操作，并且仍是安全的空操作。
- **冲突安全。** 文章锁定 / 「其他人正在编辑」（核心的 heartbeat 锁），
  以及草稿的 localStorage 安全网，即使在
  第一次自动保存。
  ✅ *已于 2026-07-05 发布* — 锁定功能依托核心自身的 `_edit_lock`
  （`minimal-admin/v1/posts/{id}/lock`；Minimal、classic 和 Gutenberg 彼此均可识别；
  接管对话框，30 秒刷新同时用于检测接管；在只读状态下显示横幅，
  完成后，在离开时发布，包括来自 pagehide 的 `sendBeacon`）。崩溃防护网会捕获快照
  在约 1.2 秒内将每次编辑写入 localStorage，并在下次打开时提供恢复（包括
  从未保存的新文章），并在成功保存后自行清除。套件：`tests/lock.test.js`，
  `tests/localnet.test.js`。这也为 Horizon 3 的在线状态奠定了基础。
- **输入长尾。** IME/组合输入、移动 Safari、无障碍。
  - **IME / 组合输入（CJK）。** ✅ *已于 2026-07-12 发布* — 每条 keydown 路径都
    `preventDefault` 的可打印按键或抢占 Enter/Backspace 时会退出
    `isComposing` / keyCode 229：Markdown 包裹 + 代码边缘转义、岛
    触发、斜杠菜单 Enter、figcaption Enter。真正的 IME 引擎不在
    无头 Chrome；`tests/ime.test.js` 会合成类似组合输入的
    KeyboardEvents。
  - **移动 Safari 检查。** ✅ *已于 2026-07-12 发布* — `visualViewport` 写入
    `--minimal-kb-inset`，因此固定底部 Chrome（统计药丸、提示）位于其上方
    软件键盘；`viewport-fit=cover` + 安全区域内边距；更大的
    工具栏/芯片/查找在手机和粗指针设备上的命中区域；正文内边距
    位于统计信息圆角标签下方；查找输入框为 16px（不会触发 iOS 聚焦缩放）。固定工具栏
    保留 `-webkit-sticky` + 不透明背景。套件：`tests/mobile-editor.test.js`
    （手机视口 + 模拟键盘内嵌区域；不是真实的 iOS 设备）。
  - **无障碍检查。** ✅ *已于 2026-07-12 发布（首个版本）* — 格式化
    工具栏是 `role="toolbar"`，包含带标签的工具；正文是多行
    文本框；岛屿、表格、图像、代码芯片携带 `aria-label`；斜杠菜单是一个
    带有 `aria-activedescendant` 的列表框；区块弹出层（表格/图片/代码/
    链接/检查器）是模态对话框，支持 Escape 关闭 + 初始焦点；
    提示框是 `status`/`alert` 活动区域；锁定接管是 `role="alert"`。
    套件：`tests/editor-a11y.test.js`。不是完整的 WCAG 审计（没有焦点陷阱
    环、无 axe CI）— 这些面向命名作者的便利功能。
- **内联媒体流程。** 从剪贴板粘贴/拖动图片，直接进入媒体
  插入符处的库；内联 figcaption 编辑。
  ✅ *已于 2026-07-05 发布* — 截图 ⌘V 和拖放的图像文件会上传到媒体库
  带有即时 blob 预览，以及可安全撤销的替换操作，将其换成真正的附件（id + class，
  真正的 Gutenberg 图片区块）；序列化器会跳过正在上传的内容，因此自动保存可以
  永远不要存储 Blob URL。每张可编辑图片都有一个可输入的标题（「写一
  「标题文字……」占位符；空标题永远不会被序列化；Enter/Backspace 边界保护）。
  套件：`tests/media-flow.test.js`。修复该套件还发现并修复了一个
  此前存在的竞态：较晚的编辑器重新渲染可能在一次
  保存（renderEditor 现在会在内容有修改时采用实时 DOM）。

## Horizon 2 — 愉悦（0.7–0.9）：Gutenberg 永远不会带来的体验

主题是：只有在*写作*工具中才有意义的功能，在这里平静的界面
这一点。截至 v0.13.0，该范围已确定（写入统计信息 + 斜杠命令扩展
曾是最后的项目）。

- **大纲面板。** ✅ *已于 2026-07-05 发布（v0.8.0）* — 标题目录作为最后一个侧边栏
  卡片，固定；按统计节奏重建；点击 ping 位于滚动器内部的
  内容坐标。大纲*模式*（⌘⇧O）会折叠导航及除最后一个侧边栏卡片外的所有
  大纲。套件：`tests/outline.test.js`。
- **专注模式。** ✅ *已于 2026-07-05 发布 / zen 于 2026-07-06 发布* — 插入符区块变暗带，
  打字机式滚动（即时步进设有上限；平滑滚动会被插入符显示取消），
  禅模式折叠导航栏和编辑器侧边栏。⌘⇧D 调色板命令（不是工具栏图标）。套件：
  `tests/focus.test.js`.
- **修订差异。** ✅ *已于 2026-07-05 发布（v0.8.0）* — 历史记录卡片打开并排
  与当前序列化器输出的单词差异（未保存的编辑也计入）；LCS 与 sameRatio
  门控，让无关的添加/删除段落保持分离。套件：`tests/revision-diff.test.js`。
- **内部链接选择器。** ✅ *已于 2026-07-05 发布（v0.8.0）* — 链接弹出层 URL 字段
  会搜索非 URL 文本中的 `wp/v2/search`；选择后立即应用。套件：
  `tests/link-picker.test.js`.
- **查找和替换**，限定在文章内并理解 Markdown。
  ✅ *已于 2026-07-10 发布* — ⌘⇧F（从 ⌘F 重新绑定，以便浏览器保留普通查找；此外还有一个
  ⌘K 命令）。匹配针对作者所看到的文本运行：每个区块中的文本节点连接起来，因此一个
  匹配会跨越内联标记（拆分的 `<strong>`），但绝不会跨越区块边界，并且岛 /
  `contenteditable=false` 子树会被完全排除。高亮是其中的覆盖矩形
  将滚动器定位在内容坐标处（不会触及输入表面）；替代选择
  匹配 Range 并运行 `execCommand insertText`，因此每次替换都是原生撤销
  入口，而「全部替换」按从后到前应用，以保持之前的范围有效。锁定模式会
  一直到浏览器查找。套件：`tests/find-replace.test.js`。
- **真正有用的写作统计。** ✅ *已于 2026-07-12 发布（v0.13.0）* — 固定药丸
  会话增量（本次打开后首次编辑以来的字数；基线会在
  文章干净，避免晚到的岛预览增加「会话」数值），以及可选的字数
  目标（全局，localStorage `minimal-writing-goal`，点击药丸即可设置/清除）。目标达成
  显示绿色。套件：`tests/writing-stats.test.js`。
- **斜杠命令扩展点。** 已发布：`minimal_admin_editor_commands` 过滤器，用于
  插件添加自由格式的斜杠条目（样板 `html`、岛 `template`，或异步
  `route` 返回任意一个结果）。纯描述符，不使用第三方 JS。记录于
  `docs/for-plugin-authors.md`；套件 `tests/editor-commands.test.js`。插件内容
  其中一半已在 v0.9.0 发布：自动插入区块、设计库、每个已注册的模式
  在斜杠菜单中（`insertPatternIslands()`；套件 `tests/patterns.test.js`），以及
  ⌘/ 上的浏览全部区块选择器（`openBlockPicker()`；套件 `tests/block-picker.test.js`）。
  v0.23.0 将用户自己的已同步和未同步模式添加到了斜杠菜单和选择器中，
  在内容切换器中包含一个 Patterns 条目（套件 `tests/user-patterns.test.js`）。

## Horizon 3 — 编辑器即平台（1.0+）

- **在线状态**（还有谁打开了这篇文章），基于核心锁而不是
  发明协作基础设施。首批切片已发布：v0.19.0 周期
  关闭了锁定故事最后的盲区（保存会携带 `X-Minimal-Expect-Lock`
  服务器端验证了标头，因此被移出的会话绝不可能静默覆盖；
  重新获得锁定时检查服务器的修改时间戳，并提供「加载他们的版本」），
  并且 v0.20.0 内容列表显示一个「{name} 正在编辑」标签，读取自核心的
  自己的编辑锁。v0.21.0 加固了接缝：公开 REST 读取不再透露
  锁定持有者的姓名（编辑信号仅用于仪表盘，而非公开给所有人）。
  超越锁模型的实时光标 / 多人在线状态仍是开放的 1.0+ 事项
  问题；截至 v0.24.0，代码中除锁模型外不存在其他机制。
- **支持离线容错的起草**，前提是 Horizon 1 的 localStorage 网络机制经验证可行。
  v0.24.0 仍未完成：没有上线专门的离线工作（app.js 不包含
  连接感知）。网络机制仍在持续证明自己：崩溃安全网
  已由套件覆盖（`tests/localnet.test.js`），而 v0.21.0 的过期 nonce 恢复
  意味着标签页整夜保持打开也会再次保存，无需重新加载。
- **营销转向。** FeiCode 仓库以编辑器为主角：首屏主视觉是写作
  层面，管理后台是「并且配套了更完善的管理后台。」自述文件和
  截图如下。当前已完成的内容（v0.21.0）：FeiCode 仓库是插件列出的
  带有可分享文档页面的网站，而 readme.txt 已不复存在（readme.md 和该网站
  都是列表界面）。剩余部分：编辑器主导的首屏本身；readme.md 仍然
  以「重新构想的 WordPress 管理后台体验」开头，并配有 Overview 截图，
  而不是写作界面。

**北极星：** Minimal 是 WordPress 的写作编辑器。Gutenberg 是布局工具。
作者端契约见 [content-blocks.md](content-blocks.md)。

永不构建：列/组/封面作为实时布局画布、模式或设计**创作**、
页面构建、FSE、托管第三方区块编辑器 JS、重新生成静态 `save()` HTML、
或将「区块对等性」作为 KPI。

可以（不属于永不构建清单）：在插入点插入已完成的模式/设计库标记作为
岛；编辑岛内的内容、文本/图片/属性；发布**内容区块**，使其
Minimal 完整编辑（动态 + schema-first）。

岛让「不支持布局区块」的代价变小 — 它能显示、保留，并且
可以通过服务器允许的检查器进行配置。如果文章大部分是布局，
Gutenberg 是正确的工具，交接只需点击一次。这份清单让编辑器保持
很好。

## 工程立场

- **保留无构建步骤。** 单文件，分区清晰。如果编辑器扩大到原来的两倍
  文件，它会让文件变成两倍大 — 在这个规模上，可搜索性胜过架构炫技。
- **测试套件是仓库公民**（自 2026-07-05 起完成）。Playwright 套件
  位于 `tests/` 中，共享辅助函数和约定位于 `tests/README.md`；一个
  在 v0.18.0 之前，顺序执行的全套件运行器让全部 171 个套件均通过，并且它是
  发布节奏；v0.24.0 时套件数量达到 206。编辑器错误修复
  仍会随附一个移植后的套件。
- **安全模型已冻结。** `editorModeFor` → classic/blocks/locked，字节级一致
  岛、必须能够由 DOM 复现的属性白名单。新能力扩展
  逐一验证允许列表中的属性（参见 editor-direction.md）；它们从不
  放宽模型。
