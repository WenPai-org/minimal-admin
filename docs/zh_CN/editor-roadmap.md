# 编辑器路线图 — 长期计划

*状态最后于 2026-08-09 根据代码核验（v0.26.0 周期，尚未发布）。
该计划服务的可衡量目标位于 [roadmap.md](roadmap.md)；本文档记录
编辑器理念、已交付账本和开放前沿。*

**论点：编辑器就是销售功能。** Minimal Admin 起初是「更平静的管理后台」，但
编辑器决定产品成败。管理后台的其余部分只是配角 —
出色的配角，但没人会为了更好看的插件页面而切换管理后台。人们
根据*写入位置*切换工具。

## 为什么这很现实

- **需求已得到验证但尚未满足。** Classic Editor 拥有五百万以上活跃
  在 Gutenberg 发布多年后仍有人安装 — 这是对「不要区块编辑器」的持续支持，
  目前由冻结的技术提供支持。Minimal 是现代答案：精通 Markdown、
  即时、平静。
- **锁定顾虑已解决，这就是护城河。** 每个此前的「安心写作」
  WordPress 编辑器曾因两种担忧之一而消亡：*我的内容被困在你的格式中*
  或*你的编辑器会破坏我的布局*。Minimal 存储原生 Gutenberg 标记（打开任意
  文章在区块编辑器中，随时、永久）以及区块岛保留复杂布局
  字节级一致。没有竞争者拥有这种说法；Gutenberg 本身也无法提供「平静的」
  其中一半。
- **写作场景占编辑工作的 90%——而自嵌套周期以来，布局形态
  其余部分也会打开供写作使用。** 段落、标题、列表、引文、代码、图片、表格、
  嵌入内容，以及现在位于组、列、cover 和 media-text 内的文本。

## 定位

**「WordPress 的写作编辑器。」** 而不是「一个功能比……更少的编辑器」。
Gutenberg」 — 不同工作使用不同工具。Gutenberg 是布局工具；Minimal 是
写作发生的地方；islands 和一键交接是连接两者的缝合线。
说「那是 Gutenberg 的工作」是策略，而不是需要道歉的限制。

「它能工作」的标准：**真实生产站点上的每篇文章都能被编写并
在 Minimal 中完整编辑，无需打开区块编辑器一次。**Dogfooding 是
路线图的裁判——已在 [roadmap.md](roadmap.md) 中正式定义为目标 1。

## 细节问题账本（工程知识，保留）

编辑器要经受上千种细微行为的检验，而 contenteditable 在每一种行为上都在反抗
一项。到目前为止的账本，全部已修复并通过回归测试：Chrome 会重新平衡空白
在内联边界处进行破坏性处理；`insertHTML` 将 `<code>` 重写为带样式的 span；
列表嵌套在其源段落中；整区块删除会将相邻内容合并为
残余外壳；不可编辑的岛通过一次相邻 Backspace 消失；选择消失
进入任何模态框；`execCommand('strikeThrough')` 会生成过时标签；对齐
通过 `justify*` 写入的样式会被序列化器剥离。**每个未来功能都要为
这一类争斗**——浏览器级别的 Playwright 验证循环不是可选项
额外开销，这是编辑器赢得信任的方式。

两个关于界面定位的推论（2026-07-11）：任何必须在视觉上跟随
滚动内容位于滚动容器内部的内容坐标中（fixed 定位
按每个滚动帧追踪的界面会落后于合成器；ResizeObserver 会在真实
重排），而逃逸到 fixed 定位的面板会在祖先滚动时关闭
像原生 select 一样，而不是追逐（combobox）。

## Horizon 3——作为平台的编辑器（开放前沿）

- **在线状态**（还有谁打开了这篇文章），基于核心锁而不是
  发明协作基础设施。迄今已交付：锁定故事的盲
  窗口已关闭（v0.19.0 `X-Minimal-Expect-Lock` 保存验证；「加载他们的版本」
  重新获得焦点时），内容列表会显示「{name} 正在编辑」芯片（v0.20.0），而公开
  REST 读取不会泄露持有者姓名（v0.21.0）。实时光标/多重在线状态
  超出锁定模型的部分仍是开放的 1.0+ 版本问题；锁定模型之外的内容均
  已存在于代码中。
- **离线容错起草**，前提是 localStorage 网络继续证明其可靠性。仍然
  开放：app.js 不携带连接意识。该兜底已有套件覆盖
  （`localnet`），过期 nonce 恢复（v0.21.0）意味着打开一夜的标签页可以保存
  无需重新加载。
- **营销转向。** FeiCode 仓库以编辑器为主角：首屏主视觉是写作
  界面，管理端就是「它周围还有一个更好的管理界面」。已上线：
  FeiCode repository 是插件列出的网站，提供可分享的文档页面；readme.txt 是
  已不复存在。剩余部分：编辑器主导的 hero 本身；readme.md 仍以「一个重新构想的
  WordPress 管理体验」配一张概览截图，而不是写作界面。

## 我们永远不会构建的内容（保持不变，承重部分）

**北极星：** Minimal 是 WordPress 的写作编辑器。Gutenberg 是布局工具。
作者端契约见 [content-blocks.md](content-blocks.md)。

永不构建：列/组/封面作为实时布局画布、模式或设计**创作**、
页面构建、FSE、托管第三方区块编辑器 JS、重新生成静态 `save()` HTML、
或将「区块对等性」作为 KPI。

可以（不属于永不构建清单）：在插入点插入已完成的模式/设计库标记作为
island；island 内的内容编辑文本/图片/属性（以及自嵌套周期以来，
直接写入核心容器）；交付 **内容区块**，让 Minimal 编辑器完全
（动态 + 以 schema 为先）。

岛让「不支持布局区块」的代价变小 — 它能显示、保留，并且
可以通过服务器允许的检查器进行配置。如果文章大部分是布局，
Gutenberg 是正确的工具，交接只需点击一次。这份清单让编辑器保持
很好。

## 工程立场

- **保留无构建步骤。** 单文件，分区清晰。如果编辑器扩大到原来的两倍
  文件，它会让文件变成两倍大 — 在这个规模上，可搜索性胜过架构炫技。
- **测试套件是仓库公民**（自 2026-07-05 起）。套件位于 `tests/`
  遵循 `tests/README.md` 中的约定；顺序式全套件运行器是
  发布节奏。编辑器 bug 修复仍会随移植后的套件一起发布。
- **安全模型已冻结。** `editorModeFor` → classic/blocks/locked，字节级一致
  岛、必须能够由 DOM 复现的属性白名单。新能力扩展
  逐一验证允许列表中的属性（参见 editor-direction.md）；它们从不
  放宽模型。
- **感受是经过测量的，而不是假设的。**`tests/perf-editor.bench.js` 报告每次按键的
  在长篇/嵌套/重型文档之间的延迟；当某个周期涉及到时，在发布切点运行
  编辑器渲染，并通过替换资源文件与上一个标签进行 A/B 对比（配方位于
  `tests/README.md`）。它产生的一条硬性规则是：**任何选择器中都不能有 `:has()`
  `#minimal-editor-body`** 中的匹配项——它会在每次
  次按键（v0.26.0 芯片密度优化在嵌套页面上测得每次按键约 300ms
  在重写为事件集标记类之前）。
